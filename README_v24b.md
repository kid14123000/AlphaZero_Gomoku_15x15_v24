# v24b —— v24 原版 + 唯一改动（黑方空盘首手走「最均衡」的一手）

基座：本仓 `Gomoku-v0_pt_v24.py`（v24 原版，未改动）
配套：`Gomoku-worker_v24.py` → `Gomoku-worker_v24b.py`（只改了它 import 的模块名）

## 改了什么（只有一处行为）

空盘（`move_no == 0`）时，黑方不按搜索走，而走**落子后 |value| 最小**的那一手：

```
对中心 5×5 的每个空点：
    把本方子放上去 → 网络前向 → 取 |value|
取 |value| 最小的前 3 手里随机挑一个
```

- 只替换落子位置；返回的 `prob` 是单手 one-hot（首手不参与 policy 监督，不影响后续）
- 开关：环境变量 `GOMOKU_BALANCED_FIRST`，默认 `0`（关）

## 为什么用 |value| 而不是 value 正负

v24 的输入是 **ch0=我 / ch1=对手 / ch2 恒 1 / ch3=last_move**（`make_input` 里写死）。
ch2 恒 1 意味着网络看不到「我是黑还是白」，所以 value 的正负只表示"输入里 +1 一方"
的局势高低。判断均衡只需比较绝对值。

## 两个必要细节（不这么写会翻车）

| 细节 | 原因 |
|---|---|
| 候选限定中心 5×5 | 不限的话冷网络会在边角点上"恰好估值≈0"，那是估值错误不是真均衡 |
| 在 \|value\| 最小的前 3 手里随机 | 纯 argmin 会让每局首手完全一样（实测确认过） |

## 实测（权重 it73_v24，CPU）

```
空盘 value（黑先手）          = +0.6976        ← 与历史记录 +0.698 吻合，说明通道语义对
均衡首手 6 次抽样:  (5,5) |V|=0.176 / (5,9) 0.245 / (9,5) 0.091   ← 有梯度、落在中心
v24 默认（200 sims）首手: (6,9) |V|=0.765                          ← 明显更极端
```

## 新服务器怎么跑

```bash
# 1) 拷整个目录（含 v24b 主脚本 + worker + 启动脚本）到训练机
scp -r . user@<host>:~/v24b

# 2) 装依赖（与 v24 原版一致）
pip install torch numpy pandas gym "gymnasium" boardgame2

# 3) 两组对照（唯一差别是 BALANCED_FIRST）
BALANCED_FIRST=1 ./run_v24b.sh      # 均衡首手
BALANCED_FIRST=0 ./run_v24b.sh      # 纯 v24 基线
```

`run_v24b.sh` 会 `export GOMOKU_BALANCED_FIRST`，工兵子进程自动继承。

可调：
```bash
REGION=5 TOPK=3 BALANCED_FIRST=1 ./run_v24b.sh   # 候选区 / 随机池大小
PY=/path/to/python ./run_v24b.sh                 # 指定解释器
```

## 该怎么判读（建议）

| 指标 | 看什么 |
|---|---|
| **白胜率** | 平衡开局的核心目的：把先手红利让出来，白胜率应上升 |
| **首手分布** | 应集中在中心 5×5 内的少数几点（不是单一点，靠 topk 随机保证多样） |
| **均手 / 速杀率** | 若出现大量 9~11 手速杀，说明均衡手选歪了（value 判错） |
| **对照** | 必须与 `BALANCED_FIRST=0` 同种子、同 sims、同局数对比，否则不可归因 |

## 已知局限

1. 判据用的是**网络原始 value**（25 次前向），不是搜索后的 Q —— 便宜但会被 value 校准度限制
2. v24 的 value 是"无执色"语义，跨代换权重时其绝对值分布会变，均衡手可能跟着漂
3. 首手手工指定 ⇒ 首手样本的 π 是 one-hot，与其他手的搜索分布不同源（首手占比极小，影响可忽略）
