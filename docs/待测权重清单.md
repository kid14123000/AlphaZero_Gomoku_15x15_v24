## 四、评测操作

```bash
# 1. 杀僵尸（每次评测前必做）
ssh m4 '~/AlphaZero_Gomoku_15x15_v4/.venv/bin/python ~/pk_v24c/kill_zombie.py 20'

# 2. 确认没有已在跑的（或 <2 个）
ssh m4 'ps -eo args | grep -c "[e]val_rapfi_v24c.py"'

# 3. 拉权重（4 分片并行）
ssh -p 41302 root@connect.nmb1.seetacloud.com "cd /root/workspace/run_v24b/gomoku_checkpoints_v24 && tar czf /root/w.tar.gz weights_it<IT>_v24.pt && split -n 4 -d /root/w.tar.gz /tmp/w_"
for i in 00 01 02 03; do scp -q -P 41302 root@connect.nmb1.seetacloud.com:/tmp/w_$i /tmp/w_$i & done; wait
cat /tmp/w_0* > /tmp/w.tar.gz && tar xzf /tmp/w.tar.gz -C /tmp
cp /tmp/weights_it<IT>_v24.pt /tmp/weights_v24c_it<IT>.pt && scp -q /tmp/weights_v24c_it<IT>.pt m4:~/pk_v24c/

# 4. 跑 40 局（后台）
ssh m4 "cd ~/pk_v24c && OMP_NUM_THREADS=2 nohup ~/AlphaZero_Gomoku_15x15_v4/.venv/bin/python eval_rapfi_v24c.py --weights weights_v24c_it<IT>.pt --sims 800 --depth 7 --games 40 --seed 7 --out rapfi_d7_s800_it<IT>_g40.jsonl > rapfi_d7_s800_it<IT>_g40.log 2>&1 < /dev/null &"
```

## 五、并发与效率（实测）

| 并发 | 聚合吞吐 | 相对串行 |
|---|---|---|
| 1 | 1.20 局/分 | 1.0× |
| **2** | **1.79 局/分** | **1.5×** ← 最优 |
| 3 | 1.44 局/分 | 1.2× |

40 局单权重耗时 33~44 分钟（取决于局长）；2 并行时约 45~55 分钟两个一起完成。

## 六、踩过的坑

```
① nohup 后不能直接跟环境变量：要 OMP_NUM_THREADS=2 nohup python（不是 nohup OMP_... python）
② 僵尸 Rapfi：一个 config_d5 进程跑了 15 小时 ⇒ 每次评测前 kill_zombie.py 20
③ screen -X quit 不杀 python 子进程 ⇒ 重启训练要 pkill -f run_quick.py
④ 并行本身安全（首手/手数/胜负 10/10 一致），之前的"bug"是僵尸干扰
⑤ 20 局虚高 12~18pp（我们）；v36 不虚高 ⇒ 两边都 20 局时"打平"是假象
⑥ 终端 500s 超时打断权重下载 ⇒ 队列项会被 pop 掉，需手工补回
```
