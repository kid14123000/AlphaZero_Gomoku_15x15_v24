### 🚨 家族级发现：value 极端化根因 = α=0.03（v2 时代遗产，2026-08-29 凌晨定论）

**现象**：空盘落 1 子/天元+1子/随机散乱 7 子局面，value 对大量落点判 ±0.6~±0.99（"兴奋点"）；随机 7 子局面兴奋度（|v|>0.6 占比）v18/v19/v20b 后期 = 69-100%；子越多越兴奋（空盘 0% → 天元+1子 39-49% → 随机7子 69-100%）。

**归因链（逐项排除，证据在本地 /tmp/ 脚本）**：
| 候选 | 结论 | 证据 |
|---|---|---|
| BN γ 膨胀 | ❌ | γ 单调升(1.25→1.61)但极端度非单调(it50 峰 72.8%, it179 39.3%) |
| 结构(通道数/层数) | ❌ | v1=v18 结构逐层相同(v1 温和 11.9% vs v18 极端 85.8%) |
| 无 ReLU | ❌ | v1/v18 都无 fc 间 ReLU，结果不同 |
| 模拟量 | ❌ | v1 后期 800sim 仍温和，v18 800sim 极端 |
| 温度调度 | ❌ | v2(旧温度)/v18(新温度)都极端 |
| 数据量/过拟合 | 辅助 | v20b 29K 比 v18 1.4K 略极端；v18 后期数据充足仍震荡 |
| **α(Dirichlet 0.03)** | ✅ **根因** | v1(α=0.0045)唯一温和；v2-v20b(α=0.03)全部极端 |

**机制**：α=0.03 强探索 → MCTS 根先验被噪声扭曲 → 自对弈"瞎探索"多 → 标签噪声大 → value 学"有子局面→±1"分类（而非期望胜率回归）→ 极端化；空盘/极少子局面在训练分布外 → value 外推崩溃 → "兴奋点"最密。

**历史根源**：v1(起点)= 极简头 + α=1/N≈0.0045 + 动态模拟量 + 无温度 → value 温和但 policy 饿死（被否定）；**v2 = 为治 policy 饿死把 α 提到 0.03 + 引入温度调度 + 论文头** → policy 活了但 value 从此极端化；v3/v6 回归极简头时 **α=0.03 被保留**（只回结构没回 α）→ 0.03 成为家族默认，v2→v20b 全中招，一个月多（2026-07-27 启动）没人质疑。

**v1 温和 = 无知温和（2026-08-29 用户纠正）**：做题仅 7-10% 饿死、value 方向一致率≈随机 36-51%、MSE 0.84-1.33——它温和是因为**不懂棋所以分数都差不多，没有任何优势**。只有"做题在线 + 兴奋度低"才是健康；v1 那种温和无参考价值。

### 一句话
v21 it8-9 实测证明**α 病在 v21 确认发作**（it8 兴奋度 21% → it9 56%，做题 top1 12.1%），但核查代码发现**真正病根可能不是 α 值大小，而是 noise 注入方式**——从 v1 就带进来的结构 bug：**每次 MCTS simulation 都重新采样 Dirichlet noise 覆盖根先验**（探索被放大 800 倍），而非论文式的"根先验加一次、800 sim 共用"。**v21b = v21 唯一改动 noise 注入方式（α 仍 0.03）**，对照验证哪一个是 value 极端化的主因。

### 🔥 重大发现：noise 注入方式偏离标准（2026-08-29 上午，代码核查）

> 📌 **发现全过程复盘（发现过程 → 线索 → 定位 → 解决）**，方法论价值极高：**"对照标准实现"能暴露"内部逻辑自洽"永远发现不了的结构 bug**——08-18 修完两个 MCTS 坑检查时说"没问题"，正是因为只查了内部逻辑（搜索量维度），没对照标准（探索注入维度）。本发现是 08-29 用户追问"又被原书坑了？"推动的。

**发现过程（时间线）**：
1. **07-27 起 20 代版本全部 value 极端化**（兴奋度 8-100%），历代瓶颈卡 100-200 代，调参/加网络均无效
2. **08-29 凌晨**：逐项排除结构/ReLU/模拟量/温度/BN γ 后，唯一一致相关变量 = α=0.03（v2 时代遗产），v1(α=0.0045) 唯一温和 → 初步归因"α=0.03 是根因"，计划 α 对照实验
3. **08-29 上午 v21 it8-9 实测**：兴奋度 21% → 56%（α 病在 v21 确认发作），触发更深代码核查
4. **用户关键提问**："又被原书坑了？" → 开始翻原书 TicTacToe 代码
5. **对照标准实现**（不是看内部逻辑）：`TicTacToe-v0_AlphaZero_torch.html` step 函数实锤

**线索（代码级）**：
```python
# 原书 step():
while self.count[s].sum() < 200:      # MCTS 200 次
    self.search(canonical_board, prior_noise=True)   # 每次都传 True!
# 原书 search() 内部:
if prior_noise:
    noise = np.random.gamma(alpha, 1., board.shape)   # 每次调用都重新生成
    prior = (1-ε)*policy + ε*noise                    # 覆盖根先验
```
- 我们 v1 原封照抄（200→sim_count=800）→ **v1 到 v21 全部 21 代都带这个 bug**
- 三方对比：原书井字棋 = 每 sim 重采样；junxiaosong = get_action 最终分布加一次（1 次）；我们 = 每 sim 重采样（继承原书）

**定位（为什么别人没炸我们炸）**：
| 版本 | 棋盘 | 合法点 | α | sim | 结果 |
|---|---|---|---|---|---|
| 原书井字棋 | 3×3 | 9 | 1/N≈0.11 | 200 | 影响被淹没（棋盘小+α温和） |
| v1 | 15×15 | 225 | 0.0045 | 50-800 | 饿死掩盖（α 极小，noise≈0） |
| **v2-v21** | 15×15 | 225 | **0.03** | 800 | **探索放大 800 倍 → 失控** |

**机制**：根先验每 sim 被不同噪声覆盖 → MCTS 树不稳定（每次模拟换探索方向）→ 自对弈"瞎探索" → 标签噪声大 → value 学"有子局面→±1 分类"而非期望胜率回归 → 极端化（兴奋度 99%）+ policy/value 背离（P/Q 来自不同搜索轨迹）。

**解决（v21b）**：noise 在 decide 层生成一次写入根先验，800 sim 共用——α=0.03 本身不是坑（论文值），**注入方式才是**。全新目录冷启动，唯一变量 = noise 注入方式。

**方法论教训（写入 blog03 坑 #42/#43 + 本清单）**：检查 MCTS 必须**对照标准实现逐项核对**（noise 注入位置/次数/α/温度/树复用，12 项清单见下），不能只看内部逻辑自洽——08-18 修"一代一树/固定模拟"时只查搜索量维度，漏了探索注入维度。

**🚨 源头实锤：原书 TicTacToe 代码就是这个结构（`TicTacToe-v0_AlphaZero_torch.html` step 函数）**：
```python
while self.count[s].sum() < 200:      # MCTS 200 次
    self.search(canonical_board, prior_noise=True)   # 每次都传 True!
```
原书 search 内部每次都重新生成 noise → v1 原封照抄（200→sim_count）→ **v1 到 v21 全部 21 代都带这个 bug**。井字棋没炸是因为：3×3 棋盘合法点仅 9 个 + α=1/N 动态（开局 0.11 温和）→ 影响被淹没；五子棋 15×15 合法点 225 + sim 800 + α=0.03 → **探索被放大 800 倍彻底失控**。**家族一个多月（2026-07-27 启动，20 代版本，历代瓶颈 100-200 代）的 value 极端化病根从第一天就在代码里，从来没有过"干净版本"**（v1 温和 = α 极小饿死，不是 noise 结构对；v2 提 α 后 noise bug 立刻引爆）。

**三方对比**：
| | α 配置 | noise 注入 | 次数/步 |
|---|---|---|---|
| 原书井字棋（v1 来源） | `1/valid.sum()` 动态 | search 内每 sim 重采样 | ⚠️ 每次 sim |
| junxiaosong AlphaZero_Gomoku | `0.3` 固定 | get_action 最终分布加一次 | ✅ 1 次 |
| AlphaGo Zero 论文 | `0.03` 固定 | 根先验加一次 | ✅ 1 次 |
| **我们 v1-v21** | v1: 1/N 动态；v2+: 0.03 固定 | search 内每 sim 重采样 | ⚠️ 每次 sim（800次） |

**v21 代码位置**（decide 322 行 + search 497-501 行）：
```python
# decide:
for _ in range(self.sim_count):        # 800 次
    self.search(canonical_board, prior_noise=noise, ...)   # 每次传 True
# search:
if prior_noise:
    alpha = DIRICHLET_ALPHA
    noise = np.random.gamma(alpha, 1., board.shape)   # ← 每次 sim 重新生成！
    ...
    prior = (1-ε)*policy + ε*noise
```
**问题**：根节点每次 sim 都用不同 noise 覆盖先验 = 探索被放大 800 倍 → MCTS 树不稳定 → 自对弈"瞎探索" → 标签噪声大 → value 学"±1 分类"→ 极端化。**α 只是放大器，noise 注入方式才是病根**（从 v1 原书代码带进来的结构，井字棋棋盘小影响小，五子棋 225 格 + 800 sim 放大到失控）。

**这修正了"α=0.03 是根因"的结论**：α 固定 0.03 本身不是坑（论文就这么干）；真正的坑是 ① noise 注入方式错（每 sim 重采样放大 800 倍）② 五子棋或许该用 junxiaosong 的 0.3 而非论文的 0.03（量级参考待验证）。

### v21b 修改点（唯一变量 = noise 注入方式）

**`Gomoku-v0_pt_v21b.py` decide 段**：
```python
# 原: for _ in range(sim_count): self.search(..., prior_noise=noise)  # 每次重采样
# 改:
if noise:
    if s not in self.policy:
        self.search(canonical_board, prior_noise=False, ...)   # 先缓存根先验
    alpha = DIRICHLET_ALPHA
    nv = np.random.gamma(alpha, 1., board.shape)
    nv *= self.valid[s]
    nv /= nv.sum()
    self.policy[s] = (1-ε)*self.policy[s] + ε*nv    # 根先验加一次 noise
for _ in range(self.sim_count):
    self.search(canonical_board, prior_noise=False, ...)   # 800 sim 共用
```
- **α 不变**：DIRICHLET_ALPHA = 0.03
- **版本标识**：VERSION="v21b" / checkpoint 目录 `gomoku_checkpoints_v21b` / worker `Gomoku-worker_v21b.py`
- **冷启动**：新目录无 weights.pt → 版本校验通过 → 从随机权重训练（与 v21 完全同条件，唯一差异 = noise 注入）
- **验证（本地 it9 权重，200 sim）**：旧版 top1 概率 0.015/熵 5.05/10次落子7种（被 noise 打散）；新版 top1 0.11/熵 4.37/10次落子3种（有棋理梯度）→ 新版搜索显著更稳定

### value 抢跑根因分析（2026-08-30 定稿, 用户追问触发）
**为什么 value 天然比 policy 先学会棋（监督信号不对称）**:
1. **任务难度差**: value 学"局面→胜率"粗粒度映射, 空盘样本 100% 黑视角+黑胜多 → 只需记住"黑先手一般赢"一个统计规律即可判对, 零棋理也能学对方向; policy 学"局面→225位置分布", 需识别活三/冲四/防守点等复杂棋形, 必须等模式在数据中反复出现
2. **信号强度差**: value 标签=终局胜负(±1)全局共享二元强烈, 第一代就有; policy 标签=MCTS 访问分布π, 早期 value 均匀→π接近均匀→交叉熵几乎无梯度, 必须等 π 有结构(依赖 value)才有信号
3. **正反馈单向性**: value 抢跑→MCTS 黑更激进→黑胜率升→数据更偏→value 标签更极端学得更快; policy 是被 value 制造的数据教, 方向被污染
**v23 反向实证**: 冻结期 value_loss 10代仅降0.12(数据多样无极端信号可抄), 解冻后 2代猛降0.27 → 标准 AZ 里 value 天然抢跑, "冻结 policy 训 value"的实质=按住 value 别抢跑, 让 policy 占住 MCTS 主导权

### Kimi 诊断升级 + ch2 Dropout 方案（2026-08-30 记录, v24 方案重大升级）
**Kimi 认栽颜色翻转后重新诊断（关键认知）**:

2. **value 空盘捷径**: board=0 时唯一可用特征 = ch2(当前执色) → 网络学"ch2=1→黑胜, ch2=0→白败" → 空盘 value 92% 不用看棋盘

**ch2 通道 Dropout（Kimi P0, 采纳）**: 训练前15代 50% 概率 mask ch2 → 空盘输入全0 → value 无法判断先后手只能输出中性 → 从根消灭空盘捷径, 强迫从 board 学; 后期逐步恢复 ch2 作为辅助特征。比随机先手干净(不改规则), 比软重置治本(灭捷径非稀释信号)

### 🚨 核心挑战（用户 08-30 提出）: 降低 noise 后的学习速度平衡
降低 noise（论文式根一次）暴露了 Q-value 死锁 → value 抢跑加速; ch2 dropout / 冻结 / λ降权 本质都是**延迟 value 利用捷径**, 但会拖慢网络整体学习速度。
**核心问题**: 怎么让 value 不抢跑（等 policy 建立棋理）又不拖慢整体训练?
**平衡手段（按侵入性排序）**:
- ch2 dropout 前15代后恢复 = 延迟而非消灭 ch2 利用（最优雅: 先逼从 board 学, 后期再给 ch2 合法信息）
- 冻结 value 先训 policy 10-20代 = 完全不学, policy 先跑
- λ_value 0.3→1.0 渐进 = value 慢速入场
- 三者可组合: 前期 policy 主导(ch2 mask + value 冻结/降权), 后期 value 入场(ch2 恢复 + λ 回升)
**本质**: value 学习快是双刃剑——标准 AZ 里快=好(快速反馈), 但五子棋无禁手黑先下 value 快=先学会 ch2 捷径=毒药。平衡点 = value 学习速度与 policy 匹配, 而非单纯加快/减慢

### 核心挑战深化: noise = 学习速度平衡器（2026-08-30 用户推断, 待行业文献验证）
**用户推断（个人观点, 非定论）**: noise 不只是探索, 本质是"多头学习速度平衡器"
- v20b 每sim重采样noise = 大量噪声 = value 梯度被稀释 = value 学得慢 = 不抢跑(苟活)
- v21b 论文式根一次 = 噪声锐减 = value 学得快 = 抢跑(死锁闭合)
- → noise 大小 ↔ value 学习速度 ↔ 抢跑与否是同一个旋钮; 降 noise 提升学习效率 = 必然放大"多头速度差"
**v23 实测印证**: 冻结期 value_loss 10代降0.12(慢) vs 解冻后 2代降0.27(快10倍); 兴奋度 it44 正215/负0 → it51 正2/负131(学太快两极跳); policy 防守探针 0→4-5(慢速渐进) → value 学习速度 ≈ policy 的 5-10 倍
**所有干预手段本质 = 调 value/policy 速度比**:
- ch2 dropout = 删捷径(不让 value 快) | 冻结 value = 速度0 | λ降权 = 慢学 | noise = 干扰学 | 池加大 = 多样统计(间接平衡) | cpuct/temp高 = 帮慢的 policy 加速
**为什么标准 AZ 没这问题**: 论文版池几十万局, value 从海量多样数据学, 统计平滑; 我们池仅5代(500局) → value 学到的统计又少又极端 → 速度失衡被放大 → P3(池30-50)也是速度平衡的一部分
**推论(用户观点)**: 降 noise 换学习效率的代价 = value 抢跑; 补偿不用"加回 noise"(倒退), 而是结构性手段(捷径删除/冻结/降权/大池)把 value 速度调到与 policy 匹配
**⚠️ 待验证**: 行业里"noise 与多头学习速度平衡"是否有类似研究, 未检索确认

**常见工程解决方案（补充备注, 2026-08-30）**:
1. **多头不同学习率**: policy 头与 value 头用不同 lr（如 value 头 lr × 0.1-0.5）→ 直接调速度比, 实现简单（param_groups）
2. **loss 权重分配**: 总损失 = policy_loss + λ_value × value_loss, λ 可固定(0.3-0.5)或按阶段渐进(0.3→1.0) → 最常用, 干净无副作用
3. **冻结/解冻调度**: 阶段式冻结（先 policy 后 value 或反之）+ 特定代数解冻 → v19/v23 已验证
4. **预训练/课程学习**: policy 先在静态题库/专家数据预训练, 再接入 value 自对弈 → 给 policy 先发优势
5. **更大回放池 + 更长对局**: 池 5→30-50 代, 对局加长(禁速杀) → 数据多样统计平滑, 减缓 value 极端
6. **探索增强**: cpuct 提高 / 温度提高 / Dirichlet α 加大 → 强制探索低先验动作, 帮慢头(policy)积累样本
7. **输入/特征干预**: ch2 dropout、颜色翻转(已否决)、8方向增强 → 删掉 value 可抄的捷径
8. **label smoothing / 软标签**: value_target 混合(0.5*V_mcts_root + 0.5*z) → 降信号强度, 有自举风险(用户方案, 评估过)
9. **定期重置 value 头**: value 极端化后重置+冻结重训 → v23 方案, 手术刀式
10. **value 头 dropout**: value 头 fc 层加 dropout(p=0.1-0.3) → 降 value 过拟合/极端化, 学得更平滑(与训练阶段可渐进衰减)
11. **ch2 随机 mask(dropout 通道)**: 训练时 50% 概率置零 ch2 输入通道 → 网络无法依赖"执色捷径", 被迫读棋盘(Kimi P0 方案, 前15代)
12. **梯度裁剪/BN 冻结**: 梯度 clip 防 value 头猛冲; 早期冻结 value_bn running stats 防统计漂移带偏
13. **EMA 权重平均 / 历史模型池**: 用 EMA 或历史弱模型做自对弈对手 → 稳定训练, 防单模型突变(对应 P4 弱对手方案)

## α×K 总浓度规律 + junxiaosong 源码实证（2026-09-01, v26 预案依据）

### 背景
v21b/v24 失衡螺旋（快攻暴涨→黑白失衡→白样本枯竭）期间, 用户提出理论: 快攻占比提升与 noise 机制改动（v21b 单次注入）强相关。核查发现更根本的因素可能是 **Dirichlet α 值本身**: 我们 α=0.03 是抄 AlphaZero 围棋参数, 未按五子棋合法动作数 K=225 缩放。

### junxiaosong 源码实证（2026-09-01 拉取, cdn.jsdelivr.net/gh/junxiaosong/AlphaZero_Gomoku）
```python
# mcts_alphaZero.py get_action (selfplay 分支):
move = np.random.choice(acts, p=0.75*probs + 0.25*np.random.dirichlet(0.3*np.ones(len(probs))))
#                                           ε=0.25     ↑ α=0.3 (不是0.03!)  ↑ K=当前合法动作数
```
- noise 注入: **1 次/步**（采样时混一次, 与 v21b+ 单次注入一致）
- ε=0.25（与我们一致）; **α=0.3（与我们 0.03 差 10 倍）**
- 先手: **固定黑先**（game.py init_board(start_player=0), 与随机先手无关）
- 训练节奏: play_batch_size=1 小步快跑 + data_buffer 连续滚动（非我们 90-1000 局/代落盘）

### α×K 总浓度规律（用户推导 + 论文数值验证）
Dirichlet 噪声形态由 **总浓度 α×K**（K=合法动作数）决定, 不是 α 绝对值:
| α×K | 形态 | MCTS 影响 |
|---|---|---|
| ≪1 | 极度尖锐（几乎只选 1 个动作） | 强迫走一条歪路, 深但极窄 |
| ~10 | 稀疏（少数动作显著, 其余≈0） | 深入评估几个意外动作 ← **甜点区** |
| ~50 | 过渡（有偏向但开始分散） | 探索面扩大, 单个不再深入 |
| ≫K | 接近均匀 | 广撒网不深潜, 探索无效 |

**AlphaZero 论文数值**: 国际象棋 α=0.3 (K≈30, 总浓度≈9); 将棋 α=0.15 (K≈80, 总浓度≈12); 围棋 α=0.03 (K≈361, 总浓度≈10.8)。**总浓度都≈10**。

**五子棋结论**: K=225 → 建议 α≈10/225≈0.044（0.04-0.05）:
- **0.03 太小**（总浓度 6.75, 太尖锐: 噪声只砸中少数点, 先验被随机尖刺绑架 → 数据坍缩到少数线路 → 黑白失衡/崩盘候选根因）
- **0.3 太大**（总浓度 67.5, 太平坦: 每个动作都沾光但不深探, 探索无效但无害 → junxiaosong 靠"宽浅探索+海量样本"跑通, 并非参数对）

### v26 实验设计（用户拍板 2026-09-01）
- **唯一变量 = α: 0.03 → 0.05**（按 10/K 缩放, 比 0.03 宽一点、比 0.3 尖锐得多）
- 其他全同 v24: 100 局/代（主 10 + 9 工兵×10）, ch2 恒1, 温度调度 v24 版, 单次 noise 注入, 8 方向增强
- 跑在**用户新机器**（非老 4090 服务器）
- **10 代内快速验证**: 若 α=0.05 黑白平衡（失衡比 <2.5:1 且白快攻样本 ≥20 局/代）→ 确认 0.03 尖锐是失衡主因; 若仍失衡 → 样本量/其他因素
- 对照: v24（α=0.03, 100局/代, it26 崩） vs v26（α=0.05, 100局/代, 预期健康）

### 纪律提醒
- v25 在跑（样本量实验, α 仍 0.03 不变）: it8-15 是判定窗口, 若失衡螺旋启动, α 是头号干预点（0.03→0.045）

## v27 λ_value 降权实验（2026-09-02 12:49 部署, 新机 2080Ti）

### 实验目的

### 决策链（用户拍板 2026-09-02）
- **约束**: ①一次只改一个 ②不动游戏规则(随机先手✗) ③不动样本(白胜样本加权✗)

## v31 部署（2026-09-04 20:30 启动, B方案: forced playouts 治白防饿死）

- **实验定义**: 唯一改动 = **search() UCB 前插入欠访问强制轮候**(KataGo 式 forced playouts); 其余全同 v30(极简value头 + c3.5 + α0.05 + 线性温度 + 根一次noise)
- **机制**: `FPU_FORCE_K=12`, 每层若存在 count < ceil(max_count/12) 的合法点 → 在其中**均匀随机**采样(不走 UCB)→ 保证每个合法点至少被访问 最热点/12 次
- **关键设计修正**: 初版按先验比例采样无效(低先验防守点仍饿死) → 改**均匀随机**(KataGo 轮流强制 = 每欠访问点等概率被轮到)
- **功能测试实锤饿死(本地 400 sim 中盘)**:
  | | v30(无FPU) | v31(FPU) |
  |---|---|---|
  | 访问到点数 | 36/213 (17%) | **213/213 (100%)** |
  | 最热点访问 | 364(垄断91%) | 13(摊薄) |
  | 访问2次点 | 0 | 174 |
  → v30 最热点独占 91% 访问、177 点饿死 = 白防饿死微观实锤; v31 100% 覆盖
- **代价**: 最热点深度削减(364→13) = 广度优先 trade-off(五子棋必须防所有威胁, 广度对)
- **启动**: 20:30:42 冷启动成功, 局速 ~88s/局(未翻倍, 开销可控)
- **假设**: 白防点被强制访问 → 防守样本进数据 → value 学到"白能防" → 空盘捷径不建立 → 白不崩
- **判据**: 对照 v30(it13 崩/it16 8%)——白胜率 it13+ 稳住 ≥40% = 白防饿死确为病根; 仍崩 = 单次注入机制死刑

### v31 待观察指标(2026-09-04 用户担忧"强制访问低先验=浪费模拟", 记录监控项)

**理论开销分析(何时强制触发)**:
- 强制只在 count < ceil(max_c/12) 的点存在时触发; 根节点 ~213 合法点 → 前 ~213 sim 在"铺满一遍"(每点至少1次), 之后大多走正常 UCB(800 sim 中强制约占前 27%)
- 深层节点访问总量本来就少(可能共 20 次), 强制改变"这 20 次怎么分配"非"多花 20 次" → 深层开销有限
- 均匀采样只作用于欠访问点, 最热点不在 under 集合内(已达标) → 热点不被抢

**真实代价 = 热点深度削减**(功能测试 400sim: 最热点 364→13, ~28x 浅化) → 风险是"攻击线钻不深 → 杀棋找不到", 非单纯浪费

**待观察指标(每代拉取)**:
1. **平均/中位局数**: v30 代0 中位 ~61 手。若 v31 局数暴增(>100手 分不出胜负) = 双方杀不死 = 过度摊薄(广度牺牲深度过度)
2. **快攻占比(≤20手)**: v30 it8-10 = 14-23%。若 v31 快攻跌到个位数 = 黑攻击线被切断 = 过度; 若维持 10-25% = 强制未破坏基本棋力
3. **白胜率轨迹(it8-13 判决)**: 核心目标——撑过 v30 崩点 it13 且 ≥40% = 白防饿死确为病根
4. **每局耗时**: 强制是否显著拖慢(若 >150s/局 = 开销异常)

**缓解预案(若过度摊薄)**:
- 调参: K=12 → 25/50(放宽配额, 热点保留更多深度)
- 动态 K: 根节点大 K(保深度) / 深层小 K(强制覆盖)——饿死在深层, 根其实不需宽覆盖
- 观察窗口: it0(it1 落盘后看局数/快攻, 最快信号) → it8-13(判决)

### 每sim vs 根一次 noise 量化实验(2026-09-04 晚, 用户问"探索深度/广度差多少")

**方法**: 同模块(v29)同权重(it5, 双层头)同局面, 只差 noise 注入方式 — 800 sim 对比
- 每sim: 800次 search(prior_noise=True) ← v20b 行为(每 sim 每层重采样)
- 根一次: 根混 noise 一次 + 800次 search(prior_noise=False) ← v21b-v30 行为
- 指标: root 覆盖% / 饿死点 / Gini 集中度 / 堵点访问

**结果表**:
| 局面 | 机制 | root覆盖 | 饿死点 | Gini | 堵点访问 |
|---|---|---|---|---|---|
| 空盘 | 每sim | 100% | 0 | 0.16 | - |
| | 根一次 | 39% | 138 | 0.46 | - |
| 白防活三 | 每sim | 100% | 0 | 0.17 | 11 |
| | 根一次 | 26% | 162 | 0.66 | 28 |
| 中盘8子 | 每sim | 100% | 0 | 0.16 | - |
| | 根一次 | 47% | 116 | 0.68 | - |

**结论1 - 广度差 2-4 倍, 饿死是根一次的数学必然**: 根一次每次搜索 53-74% 合法点从未访问(225格×800sim, 热点垄断后必然大片饿死), 其中含防守点。非"偶尔发生"
**结论2 - Gini 揭示本质**: 每sim = 强制均匀(0.16-0.17, 近似广度优先); 根一次 = 热点垄断(0.46-0.68, 深度优先)。每sim noise 的"探索" = 把 MCTS 摊平成均匀分布, 代价 ≈0 深度(棋力天花板低)
**结论3 - 两个极端各有致命伤**: 每sim(v20b)广度100%但无深度(304代不崩棋力钝); 根一次(v21b-v30)深度好但26-47%覆盖(116-162饿死→崩)
**结论4 - v31 forced playouts = 中间解**: 根一次(保深度)+ 强制补饿死点(修广度); 量化判据: 覆盖应 >90%(vs v30 26-47%)且 Gini 0.3-0.5(介于两者, 不过均匀); 若覆盖上去仍崩 = 饿死非唯一病根
**核心洞察**: v20b 不是"探索更多", 是"被迫均匀"(每sim重采样无意实现 forced playout 效果, 防守点不饿死); 根一次让搜索回归"理性深度优先"却暴露 UCB 在 225 格大棋盘缺陷: 先验主导 + q=0 乐观默认 = 低先验点永远饿死。脚本: /tmp/explore_compare4.py

### v32 候选: 周期性重置 value 校准法(2026-09-04 晚, Kimi 提供 + 用户理论背书)

**方案**: 每隔 N 代重置 value 头(随机初始化) + 冻结主干/policy 单独校准 M 代 → 打散 value 偏见(空盘捷径)
**用户核心理论**: policy 才是 RL 要得到的核心, 成熟 policy 可纯网络下出好棋; 初期 policy 不会选点时 value 不需要极端——
- value 钝(输出≈0)只损失搜索效率(每条线多花 sim 确认), 不选错点(选点靠 policy 先验+UCB)
- value 偏(输出错误偏见)才致命: 系统性高估黑线/低估白线 → MCTS 进错误分支 → 数据全黑胜 → 崩
- 实证: v20b value 极端化 69-100% 但 304 代不崩(每sim noise 保证数据探索, value 不反噬 policy); v21b-v30 value 偏见反噬数据 → 崩
**与历史区别**: v23/v24 永远冻结 value(卡 30-40% 天花板); Kimi = 周期性重置+短校准(学当前 policy 真实分布, 偏见无法跨周期积累)
**参数(待定)**: 重置周期 N=5-8 代(空盘漂移 it10 +0.02→it14 +0.25 约 4 代恶化, 需在固化前打断); 校准期 M=2-3 代(value_loss it0-3 下降轨迹); 或动态触发(空盘 value > +0.08 即重置)
**依赖**: 需新写 freeze_value_only(反向冻结: 冻结主干+policy 只训 value; v20 有 freeze_policy_only 可参照)
**与 v31 关系**: 互补(数据端 + 训练端); 但依赖数据不再单边——若 v31 修好数据仍崩 = value 偏见独立病根 → v32 启用; 若 v31 数据仍单边, 重置只是拖延
**状态**: 备选, 等 v31 it8-13 判决后定
