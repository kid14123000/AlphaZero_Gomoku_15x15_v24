 # AlphaZero 五子棋 · 版本全史 v1 → v36

> **项目**:15×15 五子棋 AlphaZero 自对弈强化学习(PyTorch,单机 + 9 工兵分布式产局)
> **核心难题**:白棋胜率崩盘——根因是「黑先手结构性红利 + 数据单边化螺旋」,而非某个单独 bug
> **本文档**:每个版本一节,只讲三件事 —— **设计**(改了什么)、**结果**、**失败原因/成功关键**
> **详版**:各阶段细节见 `版本演进史_v1_to_v9.md` / `_v10_to_v13.md` / `_v14_起.md` / `_v18_起.md` / `_v19_起.md` / `_v21_起.md` / `_v32_起.md`

## 阅读指引:四阶段 + 一条主线

| 阶段 | 版本 | 主题 |
|------|------|------|
| ① 起步与诊断 | v1-v13 | 网络/搜索基础搭建,发现 policy 饿死、色盲、两个实现 bug |
| ② 修 value 端 | v14-v20b | 换头、换归一化、修视角通道 —— 逐步排除架构嫌疑 |
| ③ 机制单变量期 | v21-v31 | α/noise/λ/温度/c/value 头/forced playouts 逐个排除 |
| ④ 开局实验期 | v32-v36 | **Q 标签 → 让手 → 随机开局,找到解** ✅ |

> ⚠️ **重要前置**:v1-v21 的"失败原因"是在**多个重大 bug 同时存活**的环境下记录的,部分归因存疑 —— 逐条可信度分级见 **附录 A:归因可信度审计**。

**主线结论(先看这个)**:v1-v31 的崩盘来自三层叠加 —— ①实现 bug(noise 每 sim 重采样 / log_softmax / 一代一树)②value 标签用 ±1 硬标签导致极端化 ③**环境结构:固定黑先手 + 黑进攻链开局定式**。前两层修完后(v33 治好极端化)白仍崩,最终由 **v36「随机开局 3 手」从数据端解决**。

## ① 起步与诊断期(v1-v13)

### v1 — 起点:极简架构 + 动态模拟量
- **设计**:极简头(policy `conv(128→1,k3)→bn→softmax` 直出 225;value 单层 fc);主干 conv+8×ResBlock;**动态模拟量**(50→200→400→800);无温度调度、α≈0.0045、无回放池。
- **结果**:巅峰战力不弱(it84 碾压 v2 it200 = 11:3),但 **policy 熵 96 代恒 5.416(完全没学)**;value 89 代全对后 91/92 全反(棋力 85>51>91 倒挂)。
- **失败原因**:三病叠加 = policy 饿死(50 sim 期 MCTS 目标近均匀 → 梯度≈0)+ value 先涨后崩 + 布局零收敛(边角 48%、天元 1.1%)。
- **🔍 归因复核**:🟡 5.416=ln(225) 同样是 exp bug 的特征值,与"50 sim 目标近均匀"叠加作用(附录 A)。

### v2 — 论文架构:早期学霸,后期塌缩
- **设计**:论文头(policy `conv(128→4,k1)→fc(900→225)`;value 双层 `fc1(450→128)→fc2(128→1)`,**1×1 感受野看不见棋形**);固定 400 sim + 温度调度 + α=0.03 + 5 代回放。
- **结果**:it45-150 平衡期是巅峰(it69 三组 PK 全胜 v1);但深层 BN 方差塌缩 126 倍,sim 错配 PK 惨败(3:17)。
- **失败原因**:双层 fc 短期红利后深层退化;**引入 `F.log_softmax` = 先验反转 search bug 的病根**(v6/v8 沿用)。**正面遗产 = 策略配方发源地**(固定 sim/温度/α0.03/5 代池/PK sim 匹配都是它定的)。

### v3 — 对照实验:v2 策略 + v1 架构
- **设计**:架构用 v1 极简头,策略用 v2 全套 —— 解耦「架构 vs 策略」的贡献。
- **结果**:代5/8/10 PK 分别 0-4 / 2-8 / 1-9 被 v2 爆杀。
- **失败原因**:**架构决定论实锤**——策略优化救不了「学不会」的架构(单层 fc value 头 10 代不学,双层头代14 转正)。
- **🔍 归因复核**:🔴 本结论在 **4 个重大 bug 同时存活**下测出,1:9 差距被 bug 放大,"架构决定论"大概率反转(附录 A)。同代 PK 的相对比较仍有效(双方同病),绝对归因无效。

### v4 / v5 — 回放池深度 × 批次大小对照
- **设计**:v4 = 50 代深池 + 32 批次;v5 = 50 代深池 + **320 批次**(同批数据反复学 10 遍)。
- **结果**:v4 判"失败"但 **PK 复核 v4 15:5 完胜 v5**;v5 policy 被拉平(softmax 近均匀 → PUCT 的 P 项失效)。
- **失败原因**:**320 批次才是灾难**(过拟合 → policy 拉平 + 有效秩腰斩);50 代深池与 5 代回放均被否定,**32 批次是对的**。教训:只看 value 体检会误判健康,必须叠加 policy 探针 + PK。
- **🔍 归因复核**:🔴 回放池里的数据本身带 noise(每 sim 重采样)+ 一代一树污染,"批次/回放池结论"建立在坏数据上(附录 A)。

### v6 — 极简头 + 固定 800 模拟量
- **设计**:架构同 v1,策略继承 v2 但把 sim 固定为 **800**(核心变量)。
- **结果**:it18 policy 爆发(冲四应下点 7.31%)**18 代追平 v2 202 代**;PK v6it40 vs v1it84 = **19:1**;败局库 it91 达 51.7%(历史新高)。
- **失败原因**:**1ch 输入色盲是结构性病**——续跑 116 代验证「能否自愈」→ 不能(it108-115 连续色盲震荡)。视角跷跷板:双视角从不兼得。

### v7 — 混合头:v6 主干 + v2 双层 value 头(**未开训**)
- **设计**:两病(极简头稀疏盲区 / 双层头梯度困 fc)分别在不同头上,混合以图全灭。
- **结果**:拼权重侦察看似方向对,但**败局库批量打脸**(v7 拼 37.8% = 与 v2 一样差,v6 51.7% 最好)。
- **失败原因**:"v2 双层 value 好"是手工局面的假象;**判 value 质量要用败局库批量,不用几个手摆局面**。理论前提被证伪 → 不立项。

### v8 — 4ch 输入治色盲
- **设计**:**唯一改动 = 输入 1ch→4ch**(ch0 当前玩家 / ch1 对手 / ch2 常数 1 / ch3 上一步),颜色翻转 = 交换 ch0/ch1 → 颜色对称性结构性满足。
- **结果**:代4 定向互补 0.0021(vs v6 1.82);败局库 it37 = **58.7% 历史最佳**;后期 it153 成"王者"(六战全卫冕)。
- **失败原因**:**4ch 结构性解决色盲**(v6 用 116 代证明 1ch 治不好),但颜色对称 ≠ 双视角健康;**97 代训练被 log bug 判废作废重训**。

### v8 变体 — BN 亚层复位对照(r7b2-reset)
- **设计**:把最深 BN 层 res7bn2 的增益复位为 1(取消 2.03 有效增益)。
- **结果**:败局库 59.5%→54.9%(−4.6),**PK 0:10 被碾压**。
- **失败原因**:**BN 深层收缩是网络学到的必要机制,不是病**;体检低估实战影响(体检只掉 4.6 点,实战直接崩)→ 治理方向改为"让收缩更聪明"(v9)。

### v9 — BN momentum 0.3 分支实验
- **设计**:**不是新版本**,是 v8 it98 权重的分支:BN momentum 0.1→0.3(唯一变量)。
- **结果**:it120 PK **8:12 负 v8**,深层 γ 收缩照旧(mom0.3 没阻止收缩)。
- **失败原因**:无显著优势(反而负 4 分达换王级差距)→ 方案不执行,停止。

### v10 — BN 参数单独分组 weight_decay=0
- **设计**:v8 判废后重练主线;**唯一改动 = optimizer 把 BN 参数分组设 wd=0**,掐断 WD×BN 死亡螺旋。
- **结果**:BN γ 纹丝不动(vs v8 跌 14%);it50 vs v8 it50 **17:3 大胜**。
- **失败原因**:wd=0 健康确认(γ 涨是活/跌是死),但 **全系 it0-77 是"一代一树" bug 污染期产物**(self_play 每局不 reset MCTS → 跨局串扰)→ 判废,重练 v12。

### v11 — BN→GroupNorm 备用方案(**未部署**)
- **设计**:v10 基础上 BN 全换 GN(GN 对 MCTS 单样本逐节点前向友好,结构性免疫 BN 故障)。
- **结果**:登记未部署;后续由 v16/v17(9×9)14:36 判负证伪。
- **失败原因**:前提是"v10 关 wd 无效才启用",v10 有效 → 不启动(求稳正确,避免浪费 80+ 代)。

### v12 — 每局 reset MCTS(根治"一代一树")
- **设计**:v10 判废后重练;**唯一改动 = self_play 每局开头 `agent.reset_mcts()`**(回到标准 AlphaZero)。
- **结果**:对 v10 形成结构性优势(后手能力 3.5 倍、相对价值提前 ~20 代);**it158 双冠王**(内战 12:8 + 跨版本 11:9 胜 v8 it153)。
- **失败原因**:v12 最硬短板 = **防守缺失**(慢速长盘,堵率 40+ 代零改善)——项目曾因此暂停,也为后续所有版本的"白崩"埋下伏笔。

### v13 — 跨 worker 攒批推理(性能实验,演进史未记录)
- **设计**:推理服务化 —— 主进程起 Inference Server 子进程,**9 工兵走 socket 攒批**(`GOMOKU_MAX_BATCH=9`),用 GPU 批量前向替代各自单样本前向;配套 v12b 方案 A。
- **结果**:微基准显示有 2× 潜力,但端到端 **v13 ≈ v12b(提速未兑现)**。
- **失败原因**:攒批同步开销吃掉了收益;**方案 A 判死**。(同期方案 B = virtual loss 也被否决:batch>1 带来的偏差真实)→ 项目接受"每局串行 MCTS"的现实。

## ② 修 value 端期(v14-v20b)

> 这一阶段的主线是「**逐层修 value 端**」:换头 → 换归一化 → 修视角通道,一路排除架构嫌疑。

### v14 — 论文式 FC 头干净重赛
- **设计**:v12 全部修复保留,唯一改动 = 极简头换论文式 FC 头(head_channels=2、k3 保留局部棋形感知),用干净环境重验 v2 架构。
- **结果**:同代 PK 全程落后 v12(0:10 → 3:7 → it80 2:8 退役);policy loss 平台 5.07-5.16;白窗口 0-1/5 崩。
- **失败原因**:**FC 头数据效率低**(1.8 万局带不动),v12 进步速度是它的 2-3 倍;白窗口是核心结构瓶颈。修正历史结论:v2 的"双层 fc 低秩化"主因论被推翻,真凶是 log 概率 bug。
- **🔍 归因复核**:🔴 **白窗口崩的真凶是 ch2 恒 1.0(白视角全错,v8-v17),不是 FC 头**;"FC 头是病因"站不住。同代 PK 落后(双方同病)相对有效(附录 A)。

### v15 — GN 方案(**未部署即淘汰**)
- **设计**:v14 基础上仅把 BN 换 GN(治 v14 实测的 BN train/eval 不一致,验证 KL=0.000000)。
- **结果**:拍板"留备用不部署";后被 v16/v17 对照(14:36)证伪。
- **失败原因**:**train/eval 一致 ≠ 实战强**;未部署的决策是正确的。

### v16 / v17 — 9×9 GN vs BN 对照(双机)
- **设计**:唯一变量 = 归一化方式(GN vs BN),9×9 小棋盘,回答"v14 瓶颈是 BN 还是大棋盘"。
- **结果**:**PK v16(GN) 14:36 负 v17(BN)**(达碾压线);v17 黑白窗口都强。
- **失败原因**:9×9 上 **BN 碾压 GN → GN 方案死**;同时证明 **v14 的 15×15 白窗口瓶颈不是 BN 的锅**。v14-v17 四版全实验失败,主线回归 v12。
- **🔍 归因复核**:🟢 两机同配置同 bug → "GN 不如 BN"的相对结论成立;但"9×9 无白窗口病"待解释(9×9 同样带 ch2 bug)(附录 A)。

### v18 — ch2 视角通道 + MCTS 递归 + 温度调度 三修(**奠基王座**)
- **设计**:①**ch2 应编码执色**(v8 起误写成恒 1.0 → 网络 196 代"永远执黑" → 白视角评估系统性错乱 → 不防守);②**MCTS 递归 ch2 传递 bug**(第 2 层起 ch2 恒 0,深层评估全错);③温度调度修正(旧 `total_est=max_moves//2=112` 但实际仅 ~45 手 → 整局近乎全程随机采样)。
- **结果**:**PK 对 v12 全系 39:1 屠杀**;首破 Rapfi depth=1;白胜率 39.1% 首次大优。
- **失败原因**:policy/棋力健康,**输在 value 端**——value 对"对手冲四"惩罚不足 → 训练给堵点仅 ~9.7% 访问 → policy 学低堵点 → 实战不堵(攻守失衡);loss 平台 32+ 代停滞。
- **🔍 归因复核**:🔴 此处**只剩 noise bug 未清**,而 noise 的净效果正是"标签噪声大 → value 学 ±1 分类而非期望回归 → 极端化 + policy/value 背离" —— **"攻守失衡"大概率是 noise 症状**(附录 A)。

### v19 — value 头换隐藏层(+ 冻结 10 代)
- **设计**:value 头从单 FC 换成 `fc1(225→128)→ReLU→fc2(128→1)`(~30K 参),主干/value_conv 逐层完全继承 v18,冻结主干只训新头 10 代。
- **结果**:**PK it200 11:9 首胜 v18 王座**,it201 13:7 实质易主;value MAE 改善 21%。
- **失败原因**:**"会进攻的偏科生"**——黑强白弱(白窗口仍崩);换头修 value 带弱 policy(做题 59% < v18 峰值 84.4%);value 极端化"假自愈"后二次回跳深饱和。
- **🔍 归因复核**:🔴 换头路线的方向性结论(换头不是解)成立,但**主要瓶颈是 noise bug 而非头结构** —— 本版仍在治症状(附录 A)。

### v20b — policy 头保留式双分支手术(换头失败收官)
- **设计**:policy 头 = 旧 3×3(继承)+ 新 1×1(随机)→ cat → Linear,给 policy 加全局组合能力;value 沿用 v19。
- **结果**:**PK it304 8:12 负 v19**(执白 2:8 防守崩);value 极端化 59-95%。
- **失败原因**:**两次半头手术叠加** —— policy_fc 吞 ~90% 梯度 + value 饿梯度 → value 塌缩(有效秩 41 近红线)。教训:**换头应一次到位或给足适应期,不宜短间隔连环手术**。
- **🔍 归因复核**:🔴 同上 —— 换头失败的背景是 noise bug 未清(附录 A)。

## ③ 机制单变量期(v21-v31)

> 上一阶段排除了架构嫌疑,这一阶段用单变量实验逐个排除**训练机制**:noise 注入 / α / λ_value / 温度 / c_init / value 头容量 / forced playouts。
> **关键副产物**:v21b 溯源发现 **v1-v21 全部 21 代都带「noise 每 sim 重采样」结构 bug**(原书井字棋写法照抄)。

### v21 / v21b — noise 注入方式对照(全家族 bug 溯源)
- **设计**:v21 = v20b 网络原样但**从零冷启动**;v21b = 唯一改动 **noise 注入方式**(每次 sim 重采样 → 根先验只加一次、800 sim 共用)。
- **结果**:v21 it9 兴奋度爆 56%(极端化复现);v21b it1 面 value 干净(max 0.597),但训至 **it32 白胜率 5-9% 崩**(黑速杀 81-92%)。
- **失败原因**:**单次注入压不住"黑必胜定式线"**;白会防守但被打崩时不用;value 极端化 + policy 半残互为正反馈。修正 noise 未治本。

### v23 — 重置 value 头 + 冻结 10 代(死亡螺旋最后一刀)
- **设计**:value 头全随机重置,主干+policy 逐字节继承 v21b it32,**冻结主干只训 value 头 10 代**;清空旧回放池。
- **结果**:解冻后 it44-47 白胜率 24/25/21% 三连站稳,做题 it45 top1=33.3% 新高。
- **失败原因**:**冻结期只治标**——解冻后 value 学太快(2 代降 0.27)两极跳变,捷径复燃,it59-61 崩。确认 **value 学速 ≈ policy 的 5-10 倍**是结构性速度失衡。

### v24 — 真从零 + ch2 恒 1(命中"白盲物理不可能",白仍崩)
- **设计**:主干/policy/value **全随机重置**,**ch2 恒 1.0**(撤销执色编码)→ 从构造上锁死黑白视角对称。
- **结果**:it0-9 健康(白 30-54%)→ **it11 白胜率跳水 55%→36%** → it26 白 8% 崩;崩后继续跑,v24 it73 做题达 **72.5% 全场最高**。
- **失败原因**:ch2 恒 1 灭了执色捷径且视角完美对称,但**白仍崩 → 根因是「黑先手速杀 + 白斜向晚熟」的数据频率差**,单纯结构修复不够。

### v25 — 样本量实验(1000 局/代)
- **设计**:v24 全同 + 每代 1000 局(唯一变量 = 样本量)。
- **结果**:**it5 白胜率 19%、失衡 5.40:1 崩**(比 v24 it11 更早)。
- **失败原因**:大样本只延迟/缓解,**崩盘主因不是数据量,是 α0.03 尖锐噪声 + 单次注入**。

### v26 — α 系数对照(0.03→0.05)
- **设计**:唯一变量 = Dirichlet α(按论文总浓度 α×K≈10 缩放)。
- **结果**:it15 白 49% 健康(首次跑过 v24 崩盘区间)→ 但 **it21+ 二次崩盘**(it36-43 白 9/8.9%)。
- **失败原因**:α0.05 = **推迟失衡 + 一次自愈,但未根治**("崩-回-崩"周期振荡);**黑白不对称(固定黑先)是未解的结构性矛盾**。

### v27 — λ_value 降权(1.0→0.3)
- **设计**:唯一变量 = total_loss 里 value 项权重降为 0.3(治 value 抢跑),从零训练。
- **结果**:λ 确实压住了 value 抢跑,但 **it20 断崖 41%→14%**(比 v26 还早),it30-34 结构性固化。
- **失败原因**:**λ 降权非解药**——value 学速不是崩盘根因,只是放大器;**loss 创新低而行为崩 = loss 是安慰剂**。

### v28 — 温度线性降温
- **设计**:唯一变量 = 温度调度从指数衰减改为 step1-60 线性 1.0→1e-3。
- **结果**:it15 断崖(白 48%→30%)崩得更早;崩后宽幅震荡 13-56%(不固化个位数)。
- **失败原因**:**"防死透、不防崩"** —— 温度作用在采样层,防不了 policy 先验坍缩层;崩后做题暴涨 = 背熟坍缩定式 ≠ 棋力。

### v29 — c_init 加大(1.25→3.5)
- **设计**:唯一变量 = c_init(治"低先验好点访问不到"),基线 = v28。
- **结果**:**it13 白 15.7% 崩**,比 v28 更快。
- **失败原因**:c 不是杠杆——实测黑活三局面 **c 从 1.25 加到 20,防点访问仅 3→8 次(纹丝不动)**,因防点先验低、c 压不过先验盲。

### v30 — 极简 value 头(容量排除)
- **设计**:唯一变量 = value 头从双层降为 v18 式单层(30K→226 参),假设"表达力弱 = 学得慢 = 不抢跑"。
- **结果**:早期兴奋度被压住(it7 6% vs v29 22.9%),但 **it16 仍崩**。
- **失败原因**:226 参与 30K 参学出同样的空盘捷径 → **捷径来自训练信号(数据)而非网络容量**。至此 α/λ/温度/c/value 头/冻结/BN 全排除,**唯一剩 noise 机制(数据生产端)**。

### v31 — forced playouts(KataGo 式)
- **设计**:唯一改动 = search 的 UCB 前插入欠访问强制轮候(治"白防饿死");功能测试:饿死点覆盖 17%→**100%**。
- **结果**:**it7 就停**——policy_loss 8 代卡均匀线,做题 ≈ 随机,首手乱撒边角。
- **失败原因**:**policy 空转实锤** —— forced playouts 把 count 摊平(最热点 1.6% vs 91%)→ **target≈均匀 → 交叉熵梯度趋零 → policy 冻结**。治了饿死(广度)却杀死 target 锐度(深度);再试须同时锐化 target。

## ④ 开局实验期(v32-v36)—— 找到解

> 前 31 个版本的结论:**机制侧(α/λ/温度/c/容量/noise/forced)已全部排除,病根在「环境结构:固定黑先手 + 黑进攻链开局定式」**。这一阶段把矛头转向**开局**。

### v32 — 继承 v24 it73 + 重置 value 全头(手术式新起点)
- **设计**:三来源拼接 —— 网络 = **v24 it73 继承**(policy 全场最强)+ value 头全重置 + v26 搜索配置。(α 0.05 / ch2 恒 1 / 线性温度)
- **结果**:代13 即停(it12 白 8.5%),判决窗口未走完。
- **失败原因**:暴露 **value 空白死锁** —— 最小局面实证:policy 明明会防(先验 0.468 top1)但 value≈0 时 MCTS 800 sim 后防点 Q 仍 -0.013(799 节点仅 2 个到达终局)→ **中间局面 Q 全卡中性 → value 连训练信号都拿不到**。

### v33 — value 标签改 **Q 软标签**(治好极端化病根)
- **设计**:v32 全同 + **唯一改动 = value 标签从 ±1 改为 Q**(每步自己的 MCTS Q,当前玩家视角)。洞察:±1 是中盘高方差噪声,硬标签逼网络"装懂"。
- **结果**:本地 A/B 实证(A=±1 15 epoch 空盘冲 +0.401、把"四连必堵"符号教反;B=Q loss 仅 0.004 方向正确);上线 **it5-8 白胜率 43-47% 稳定(历史首次 value 学习后白不崩)**,excite6 从 v24 的 52.8% → **0.0%**。但 **it10 白 12% → it13 白 0/47 崩**。
- **失败原因**:**value 中性也崩 → 白崩 ≠ value 偏色**。机制定论:白崩 = **先手红利(~39pp)随棋力兑现 + 数据单边化螺旋**;value 偏色只是加速器。**Q 标签解决了极端化(近 30 代病根),但没解决环境结构问题**。

### v34 — 黑首手 50% 让一手(**4 纯角**):让过头了
- **设计**:v33 全配置 + 唯一改动 = 黑首手 50% 概率强制落 4 角之一(人为让先 → 供给白胜样本);种子 = v33 it8 全键继承。
- **结果**:让手局白 ~67% vs 正常局白 ~24%(首手红利 ~39pp 印证);首学后 **it6-8 正常局白 9/7/10% 三连崩,让手局白 94-98%**。
- **失败原因**:**让手让过头** —— 4 角把白拉到 96%,喂回来的是"另一个先手"而非"后手怎么活"(让手局黑胜仅 4% = 该学的后手技能样本只有 6 个);正常局白毫无改善。

### v35 — 让子改「环带 124 点」(+ v35-B 温度热改)
- **设计**:唯一改动 = 让子点 4 纯角 → **距天元 5-8 子环带(欧式 d²∈[25,64],124 点)**(目标让手局白 65-75%,留黑 25-35% 翻盘面);种子 = v34 it8。**v35-B**:温度改分段快速降温(0-3 手 1.0→0.6、4-7 手→0.15),治超短速杀。
- **结果**:让手局白 48-49%(教学样本充足);温度热改让**超短局 42%→7%、中位手数 14→23**。但 **正常局白 10 代窗口 {9,6,12,7,8,20,10,18,5,4}% 从未 ≥3 代连续爬升**;**PK it16 vs it4 = 10:10(ring 赛黑 12:白 8)= 11 代训练对种子零可测棋力增益**。
- **失败原因**:**环带让手治好了"白胜样本真空",但没教会"正常局白防自由黑"** —— 只动黑 1 打断不了黑进攻链(**黑1+黑2+黑3 连贯成型才是自由黑强的本质**)。→ v36 时机成熟。

### v36 — **随机开局 3 手**(把胜负从"执色"转移到"局面质量")✅
- **设计**:**前 3 手(黑1 + 白1 + 黑2)100% 全随机**,落在中心区互不重合(初版 7×7 49 点 → **v36b 扩到 13×13 过调 → v36c 回调 9×9 81 点**);种子 = v35 健康点全键继承。
- **结果**:✅ **成功**。代0 白胜率即 58%;**it11 20:0 完封 v18 历史王座**(黑窗口 10:0 + 白窗口 10:0)= 机制有效的终极证据;此后 **it0-194 白胜率稳定在 39-51%(中枢 ~43%)从未崩盘**,黑胜样本占比不再单边化(白胜样本自然供给);后期对局变快(中位 15-24 手、超短局常态)但黑白胜均步接近 = 双方棋力同步提升。
- **成功关键**(为什么它是解):前 3 手随机**同时打断黑的两手进攻链成型 + 消灭"黑必胜定式线"的自我强化** → 胜负从"执色"变成"局面质量",先手红利被开局可变性从**数据端**结构性抵消。这是 v1-v35 所有"修网络/修搜索/修机制"路线都没做到的事。
- **遗留**:100% 全随机训练下 policy 空盘自由先验可能弱化(部署实战需回掺正常局);随机范围需调参(7×7→13×13→9×9)。

## 尾声:v36 = 稳定期

- **结论**:跑满 **194 代**,白胜率 39-51% 稳定,棋力持续进步 → **进入稳定期**,结束 v1-v35 的"崩盘-修-再崩"循环。
- **一句话总账**:项目的病根不是某个 bug,而是**三层叠加**——①实现 bug(noise 重采样 / log_softmax / 一代一树 / ch2 视角)②标签机制(±1 硬标签 → value 极端化)③**环境结构(固定黑先手 + 黑进攻链开局定式)**。
  - v1-v18 修 ①(其中 v8 4ch、v18 ch2/递归/温度 是关键修);
  - v19-v32 修 ② 与架构(v33 的 **Q 软标签**治好极端化);
  - **v33 之后白仍崩 → 证明 ③ 才是发动机** → **v36 用随机开局从数据端解决**。
- **方法论点**:「静态指标(loss/体检/做题)是安慰剂,**实战 PK 是唯一判定**」(v19/v27/v35 三次被证伪);「体检低估实战影响」(v8 变体);「换头一次到位」(v20b);「机制侧排除法」(v21-v31 逐个单变量)。

### A.3 逐条重估

**可信度判据**
- 🟢 **可信**:在无重大 bug 环境下测得,或有独立机制证据支撑
- 🟡 **部分可信**:带 bug,但结论有构造性/结构性证据(如颜色对称性是逻辑必然,与 bug 无关)
- 🔴 **存疑**:结论与存活 bug 的净效果**同向**,且该 bug 正是这一现象的直接制造者

**一条重要区分**:**同代 PK 的相对结论在"双方同病"时仍然有效**(共同 bug 项在比较中抵消),但**"为什么会这样"的绝对归因无效**。

### A.4 三条反事实推演

**MVP 级证据:每次修 bug 都带来跃迁** —— v8 修 exp → v9/v12 立刻 BN 健康 + it158 双冠王;v12 修一代一树 → 后手能力 3.5 倍;**v18 修 ch2/递归/温度 → 立刻 39:1 屠 v12 全系**;v21b 修 noise → it1 value 立刻干净(max 0.597)。既然修 bug 的边际收益远大于所有超参/架构/机制调整,那么 v1-v20 的"失败原因"大部分应重写为"**bug 症状**"。

1. **「架构决定论」大概率反转** —— v3 的 1:9 是在 4-bug 环境下测出的;干净环境里极简头 vs 双层头的差距可能大幅缩小。
2. **「白崩」不会消失,但会晚得多、轻得多** —— 三个 bug(exp/一代一树/noise)都在直接制造"坏数据 + value 极端化 + policy 半残",而白崩的机制正是"数据单边化螺旋"的加速器。**但 v33 是铁证:干净环境下 Q 标签治好极端化,白仍崩** → 黑先手红利是独立真实存在的第二条线。
3. **「随机开局」这个解本可以更早找到** —— bug 掩盖了结构问题,让 21 个版本都在修网络/修机制(被误诊牵着走),直到 bug 清空后才看见真面目。

### A.5 审计结论

> **本全史最该修正的一句话**:现在写的是"三层叠加",更准确的是 **「bug 层掩盖了结构层」**。
> v1-v21 大家都在修 bug(同时被 bug 误导归因),v33 之后 bug 全清,**才第一次看到结构层的真面目**。
> 这也重新解释了"每一代的失败都为后一代奠定了方向":不是方向对,而是 **bug 被一个个清掉后,现象才逐渐显影**。
>
> **对写作的提示**:早期版本的真实遗产不是"某某架构/超参失败",而是**"如何发现 bug"**——v8 修 exp、v12 修一代一树、v18 修视角通道、v21b 修 noise 这四个时刻,才是项目真正的转折点。

### B.3 还没碰的(冰山以下)

| 方向 | 具体可试项 |
|---|---|
| **网络规模/结构** | 128ch→256/512、8→16/32 ResBlock、5×5/7×7 卷积、SE/注意力、CNN+Transformer 混合 |
| **搜索** | PUCT 公式变体、噪声下探到子节点、visit-count 温度锐化、KataGo 式 playout cap randomization、时间自适应 sim、多线程 MCTS、真正的批推理(绕过 virtual loss 偏差) |
| **训练目标** | policy 目标锐化(对访问分布开方/调温)、辅助任务(活三/威胁/步数预测)、TD(λ) / n-step 混合自举(目前纯终局标签)、多值头(胜率+领地) |

| **规则层** | 贴目/让子制度设计、先后手轮换开局、棋盘尺寸策略 |

### B.4 小结

- **36 个版本 ≈ 30 项杠杆**,其中真正"解决问题"的只有 **1 项**(v36 随机开局);
- **贡献最大的是 4 次 bug 修复**(v8 exp / v12 一代一树 / v18 ch2+递归+温度 / v21b noise)——每次修复都带来跃迁;
- **面最广的是"无效清单"**(换头 3 次、α、λ、c、forced playouts、大样本、温度、攒批)——这些"失败"构成了项目最扎实的方法论资产;
- **所以:v36 只是冰山一角** —— 上表 B.3 的 7 类方向基本还没碰,尤其"换权 gating"和"辅助任务"这两条,可能是下一个数量级的突破口。

## ★★★ 退化回路的根因：高温采样污染训练数据（2026-11-18 夜，实测）

### 实测方法

### ★ 完整退化回路

```
① 温度调度按「绝对手数」衰减：第1手 1.00 → 第13手 0.31 → 第20手 0.14
   ⇒ 对局若在 13 手内结束，全程处于 0.4~1.0 高温区

② 高温 = 按 MCTS 访问分布采样 ⇒ 近似随机走子
   ⇒ 随机对下时先手（黑）几乎必胜（92%）

③ 这些「高温随机黑胜局」占全部对局 30~42%
   ⇒ 喂给 value 头 ⇒ value 学到「黑从开局就赢」
   ⇒ 空盘 V 实测漂移：0.230(it63) → 0.348(it58) → 0.370(it71) → 0.381(it78)

④ 空盘 V 上升 ⇒ 开局过滤器在【空盘】就通过
   阈值 = 0.25 + 0.02 × 重抽次数（12 次上限 ⇒ 0.49）
   空盘 V=0.381 时，第 7 次尝试（阈值 0.39）即通过，手数=0
   ⇒ 实测 20 局中 5 局（25%）开局手数为 0，完全没做开局随机化

⑤ 无随机开局 + 温度从第 1 手就是 1.00 ⇒ 又是高温随机局 ⇒ 回到 ①
```

**闭环：温度高 → 黑速胜 → V 升高 → 开局过滤失效 → 温度影响更大。**

### 这解释了过去所有「看不懂」的现象

```
· 空盘 V 单调上涨：是高温随机黑胜局喂出来的，不是棋力变化
· 均手低、短局多（42%）：短局是高温产物，不是防守变差
· 白方学不会防守：白方只在低温长局里有真实决策，而长局只占一半
· 执白 20%：白方赢的局都在长局，样本少
· 「活三不堵」：短局里是随机走子；中盘 17~25 手贪心测也只有 22%（另一层问题）
```

### 结论

```
不是网络在退化，是【训练数据被自己的高温采样污染了】。
短局不是棋力下降的表现，是「随机对下」的表现，而我们把它们当成了教学样本。
```

## ★★★ 反转机制定案：温度锁 + 短局占比（2026-11-19，用户假设 → 实测验证）

### 用户假设

> 「昨天活三不堵，是因为遇到了温度锁 —— 堵点概率不够高，被高温采样锁住了。

### 实测方法

（落地率 = softmax(log p / T) 在两个端点上的概率和）

### 结果

| 网络 | p(堵端)均值 | **argmax 堵端%** | T=1.0 落地 | T=0.5 落地 | T=0.3 落地 |
|---|---|---|---|---|---|
| it43 | 21.4% | **44.9%** | 21.4% | 39.0% | 43.3% |
| it88（前一天） | 26.1% | **36.5%** | 26.1% | 35.3% | 37.2% |
| **it105（今天）** | 23.7% | **49.4%** | 23.7% | 40.2% | **45.1%** |

**假设成立**：argmax 堵端从 36.5% 恢复到 49.4%（+12.9pp），甚至超过代43（44.9%）。

### 但有个精确的细节：涨的是「判断」，不是「总概率质量」

```
p(堵端) 总概率：26.1% → 23.7%（略降）
argmax 堵端    ：36.5% → 49.4%（大涨）

⇒ 现在更常把堵端排第一，且排第一时更果断
  （以前两端各分 ~13%，现在一端 ~20%、另一端 ~4%）
⇒ 所以「总质量」没涨，但「决定性」大涨
```

### 完整体温账（这正是温度锁机制）

```

前一天（it88）同一批局面只有 36.5%
前 6 手温度 1.0 ⇒ 落地率只有 23.7%（高温段依旧锁死）

⇒ 高温段没被修好，只是【高温段的局面变少了】：
  短局(≤13手) 占比 54% → 24%
```

### 反转的真实机制 = 两条叠加

```
① 判断本身恢复：argmax 堵端 36.5% → 49.4%（回到/超过代43）
② 被温度锁影响的局面少了：短局 54% → 24%，低温决策占比上升

⇒ 两条合起来才解释 Rapfi 50% → 65%、执黑 100%
⇒ 单看任何一条都不够 —— 这就是前一天误判的根源
```

| | 理论吞吐 | 实测有效 | 每代时间 | 备注 |
|---|---|---|---|---|

⇒ 4090 的 batch=1 GPU 前向有 10~30ms/次 kernel launch 开销（800 sims ≈ 200s/局），CPU 反而只需 3.7s/局（单进程），

### 五、修法（4090 侧，改调度不改硬件）

```
现在：19 工兵 × 每兵固定 5 局 ⇒ 抽到长局的工兵拖整代

  ⇒ 每兵局数多 ⇒ 长局被平均 ⇒ 拖尾比例下降
  ⇒ 预期 50 分钟/代 → 25~30 分钟/代
```

### 六、附带结论

```
① M4 单机整机训练 ≈ 31 分钟/代，比 4090 的 50 分钟快
② 但 M4 训练期间不能做 PK 评测 ⇒ 现在"4090 训练 + M4 评测"的分工是合理的
③ 若要省钱：搬到 M4，PK 改在训练间隙跑
④ GPU 在这类 workload 上没有优势 —— 想真正提速要把 MCTS 改成批量推理凑 batch 上 GPU
```

## ★ 动态领局上线 + 4090 吞吐硬上限（2026-11-21 11:20 实测）

### 一、改动（`GOMOKU_DYNAMIC=1`，默认关闭）

**trainer 侧**：`expected` 从「工兵数×每兵局数」改为「GOMOKU_TOTAL_GAMES（默认95）」；
数够局数后写 `worker_data/stop_iter{N}` 文件，工兵各自收尾退出。

**工兵侧**：循环上界从 `GAMES_PER_ITER` 改为 `GOMOKU_MAX_GAMES`（默认40），
每局开始前检查 stop 文件，存在则退出。

价值：**每代局数与工兵数解耦** —— 以后调样本量只改 `GOMOKU_TOTAL_GAMES`；
且快的工兵多干、慢的少干，拖尾消失。

| 配置 | 工兵 | 整代时间 | 有效吞吐 |
|---|---|---|---|

| 9 工兵 × 10 局（固定） | 9 | 49 分钟 | 1.94 局/分 |
| **24 工兵 + 动态领局** | 24 | ~41 分钟 | **2.25 局/分** |

```
动态领局：✅ 拖尾消失（24 个工兵进度均匀 1~3 局，无落后者）
但吞吐只 +16% ⇒ 瓶颈不在调度
```

### 三、★ 4090 的 batch=1 前向吞吐是硬上限

```
4090 实测：约 520 次前向/秒（9 / 19 / 24 工兵都一样）
  GPU 利用率 48%、CPU 仅 12 核在跑，但吞吐上不去
M4 CPU 实测：约 1568 次前向/秒（3 倍于 4090）

⇒ 这类「每步单次前向」的代码，CPU 比 GPU 快 3 倍：
   GPU 每次前向有 10~30 ms kernel launch 开销（800 sims = 8~24 秒/步）
   CPU 每次前向只要 1~4 ms
⇒ 加 GPU、加工兵都没用；吞吐由「前向次数 / 单次开销」决定
```

### 三、四个限制（按重要性排序）

| # | 限制 | 后果 |
|---|---|---|
| ① | **继承网络的 V 偏见**：「均衡」= 当前网络认为均衡 | 若 V 系统性错判，BAL3 挑的是"骗过自己 V 的怪手"，不是真均衡 |
| ② | **只约束一个瞬间**（第 3 手后），白方第 4 手即可还回去 | 第 9/13 手可能照样定局 ⇒ 单点补丁，非持续均衡 |
| ③ | **对黑方是自残**：第 3 手强制挑让 \|V\| 最小的手 | 黑方第 3 手 policy 被污染（学会"这里不用下最强"） |
| ④ | 弃局只重开 3 次，约 10% 局面无法均衡 | 每代多约 11% 尝试，代速略慢（可接受） |
