## v1 — 起点：极简架构 + 动态模拟量

### 架构
- **简化版网络**（original / opt 两个变体，opt 加了 torch.compile + inference_mode + AMP FP16 推理优化）
- Policy 头：`conv(128→1, k3×3) → bn → softmax 直出 225`（无 fc 层，1,157 参数）
- Value 头：`conv(128→1, k3×3) → bn → fc(225→1)` 单层（1,383 参数）
- 主干：conv(1→128,k3) + 8×ResBlock(128) + BN + ReLU

### 训练策略
- **动态模拟量**（核心特征）：`iteration<20 → 50`、`<50 → 200`、`<71 → 400`、`≥71 → 800`
- **无温度调度**：落子全程按 MCTS 概率采样
- **Dirichlet α = 1/N ≈ 0.0045**（极弱探索，比标准 0.03 小 6 倍）
- 无经验回放，每代只训当前代 100 局
- 8 方向对称增强（4旋转 × 2镜像）

### 结果
- ✅ **巅峰战力强**：it84 碾压 v2 it200（11:3）、v2 it153（17:3）——强在 800 sim 高质量自对弈数据 + value 深判断
- ❌ **policy 头恒死**：熵恒 5.416（完美均匀），96 代全程没学——50 sim 期 MCTS 目标近均匀 → 梯度≈0
- ❌ **value 后期退化**：89 代全对 → 91/92 全反（loss 降但棋力崩，85>51>91）
- ❌ **布局零收敛**：125 代边角 48%、天元仅 1.1%（胜率 59.1% 却不选）
- ❌ **威胁感知天花板低**：灵敏度从未达标（<-0.05），峰值只有 v2 的 40%

**结论**：v1 是"policy 饿死 + value 先涨后崩 + 布局零收敛"的三病选手，靠窗口红利撑起巅峰。停训换 v2。

### ⚠️ 修正批注（08-14 用户补充核实）

- **v1 无 search bug**：policy 输出为全局 softmax（免疫 log_softmax 先验反转 bug）——"动态模拟量"是 v1 唯一的实验变量
- "早期低模拟把网络干废" = 当时的归因，文档依据：**50 sim 期 MCTS 目标近均匀 → policy 梯度≈0 恒死**（it0-96 熵恒 5.416 从未学）
- v1 后期废 = 三病叠加（policy 饿死 + value 89 代后先涨后崩 + 布局零收敛），非单一原因

## v2 — 论文架构：早期学霸，后期塌缩

### 架构
- **论文版网络**（注释写"与 v1 相同"但实际完全不同！）
- Policy 头：`conv(128→4, k1×1) → bn → fc(900→225)`（203,254 参数）
- Value 头：`conv(128→2, k1×1) → bn → fc1(450→128) → fc2(128→1)` 双层（58,122 参数）
- **1×1 感受野**：只看单点，看不见 3×3 内的棋形（活三/冲四）

### 训练策略
- **固定 400 模拟**（用户拍板：不做模拟量对照混杂；注释里曾有"动态 200→400"设计但最终固定）
- **温度调度**：前 15 手 T=1 → 中段线性降到 0.25 → 最后 10 手 T=0.05
- **Dirichlet α = 0.03**（标准 AlphaZero，v1 的 6 倍探索）
- **5 代经验回放**（REPLAY_POOL_SIZE=5，混合训练）
- 每代自动健康体检（health_log.json）

### 结果
- ✅ **it45-150 平衡期 = 巅峰窗口**：it69 三组 PK 全胜 v1 it84（7:3 / 6:4 / 7:3）
- ✅ **value 威胁感知强**：it202 Δwhite -1.16、威胁/子力比 9.49（v6 的 73 倍）
- ❌ **policy 梯度困死 fc**：policy_fc 吞 92-97% 梯度 → 主干收不到策略特征
- ❌ **深层 BN 方差塌缩**：res0.bn2=1.517 → res7.bn2=0.012（缩 126 倍）→ 深层残差输出≈常数
- ❌ **value_fc1 低秩化**：86→73（但 it202 反弹到 87，非单向恶化）
- ❌ **PK sim 错配**：400 训练 vs 800 评估 → it153 惨败 3:17（it69 同 sim 6:4 胜）

**结论**：v2 = 双层 fc 短期红利（早期学霸）+ 后期深层退化 + policy 方向盘坏。it202 收官停训（1.9元/时烧钱 + PK 不敌 v1）。

### ⚠️ 修正批注（08-14 用户补充核实：search bug 病根 + fc 归因存疑）

- **search bug 病根 = v2 引入 `F.log_softmax`（脚本已核实）**：v1/v3 系 policy 输出为全局 softmax（免疫），v2 写论文头时改 log_softmax → 先验反转 bug 从 v2 开始，v6/v8 沿用（v6 恢复极简头但 forward 保留了 log_softmax 写法）
- **"v2 困在双层 fc"归因不可靠**：v2 全程在 search bug 下训练——policy_fc 吞 92-97% 梯度 + 双层 fc 低秩化，到底是**结构稳态**（fc 瓶颈）还是 **search bug 假象**（先验反转污染 policy 学习），**无法确定**（缺"论文头 + 无 bug"对照，同 v6 色盲的污染问题）——待验证
- 但"固定模拟量有效"结论可靠：v1（动态 50→800，policy 饿死）→ v2（固定 400，policy 学习正常），**固定模拟量一直沿用至今**（v6/v8/v10 都固定 800）

### ✅ v2 的正面遗产（用户 08-14 补充，v10 仍在继承）

| 遗产 | 内容 | 后续传承 |
|---|---|---|
| **固定模拟量** | v1 动态 50→800 → v2 固定 400（用户拍板不混杂） | v6/v8/v10 固定 800，**沿用至今** |
| **温度调度** | 前15手 T=1 → 中段 0.25 → 终局 0.05 | v3-v10 全沿用 |
| **Dirichlet α=0.03** | v1 弱探索 1/N≈0.0045 否定，v2 增强 6 倍 | v3-v10 全沿用 |
| **5 代经验回放** | v2 引入 5 代池 | v4/v5 深池实验验证甜点位（50 代否定），v6-v10 沿用 5 代 |
| **批次 32×512** | v2 参数 | v5 320 批次过拟合否定（15:5 输 v4）→ 32 批次定为甜点位 |
| **推理优化** | v1 opt 首创（torch.compile + inference_mode + AMP FP16）→ **v2 传承并积累经验**（learn 用 raw_net 避开 CUDAGraph 坑） | v6 表标"v2 经验"，v8/v10 沿用 |
| **PK sim 匹配教训** | v2 后期 400 训练 vs 800 评估惨败 3:17 | v6/v8/v10 训练/评估统一 800 |

**定性**：v2 是"**策略配方发源地**"——固定模拟量/温度/α/回放/批次这些沿用至今的配方全部由 v2 定下；坏在架构偏离（论文头）+ 引入 search bug。v10 的"策略层"几乎全部继承自 v2。

### 训练策略（= v2 全套，脚本核实）
| 项 | 值 |
|---|---|

| 温度调度 | 前 15 手 T=1 → 中段线性降到 0.25 → 最后 10 手 T→0 |

| 经验回放 | **5 代**（REPLAY_POOL_SIZE=5）|

### 目的
解耦"**策略优化 vs 架构优化**"的贡献：v3 vs v2 同策略比架构，v3 vs v1 同架构比策略。

### 最终定论（代10 收尾，2026-08-01）

## v4 / v5 — 分支实验：经验池深度测试（都否定）

### 动机
用户想验证"**加深经验池能否让 value 更稳**"——回放池从 5 代加深到 50 代。

### 架构（v4/v5 同 = v2 论文头，权重 key 数实测确认）
- 主干 `conv(1→128,k3)` + 8×ResBlock(128)；policy `conv(128→4,k1)→fc(900→225)`；value `conv(128→2,k1)→fc1(450→128)→fc2(128→1)`（双层）
- **实测**：v4 it143_v450reply.pt 和 v5 it143_v5.pt 均 120 keys、含 `policy_fc` + `value_fc1/fc2`——架构与 v2 完全一致
- 训练脚本均 = **v2 脚本（`Gomoku-v0_pt_v2.py`）改配置**（非独立 v4/v5 脚本）；v4 权重在 `/root/gomoku_checkpoints_v2/deprecated_v450reply/`（it128-152），v5 在新机（it128-158）

### v4 配置（50 代深池 + 32 批次，老机）
- **REPLAY_POOL_SIZE = 50**（5 → 50）
- 批次 = **32**（与 v2/v6 相同）
- 其余同 v2：固定 400 sim / 温度调度 / α=0.03 / lr=0.001 / 32×512

### v5 配置（50 代深池 + 320 批次，新机实验A，training_expA.log 核实）
- **REPLAY_POOL_SIZE = 50**（5 → 50，实验A；日志"取最近 50 代…共 5000 局"）
- 批次 = **320**（= 同批数据反复学 10 遍，v4 的 10 倍训练量；日志"batches=320, batch_size=512"）
- 其余同 v2：固定 400 sim / 温度调度 / α=0.03 / lr=0.001 / 320×512

### 结果（全部否定）
- **32 批次**（v4）：棋力退步，回退 5 代
- **320 批次**（v5）：**PK 5:15 崩**——policy 头 softmax 被拉平（学成近均匀）→ PUCT 的 P 项失效、MCTS 全靠 Q 项硬撑
- **v5 的病在 policy 不在 value**：value 盲测全绿（+0.82/-0.96 等）但 policy 四类探针全灭（0/4）
- value_loss 最低（0.2393）却最菜 = "value 骗人 + policy 瞎了"
- **v5 价值头主方向独大**：有效秩 86→40 腰斩 + top1 63% 能量

**教训**：过拟合权重只看 value 体检会误判健康，必须叠加 policy 探针 + PK；**5 代回放是验证过的甜点位**。

### v4 vs v5 关键 PK（2026-08-07 复核实锤）
| 对局 | 比分 | 解读 |

| v2it143 vs v4it143 | 8:12（v4 胜）| 极简头+50池打赢论文版（v2 后期已崩）|
| v2it143 vs v5it143 | 7:13（v5 胜）| v5 也赢 v2（但弱于 v4）|
| v2it158 vs v5it157 | 13:7（v2 胜）| v2 后期赢 v5 |

**⚠️ 重要修正**（复核发现）：早期记忆"v4 失败/v5 更好"是**错的**——实际 **v4（50池+32批次）完胜 v5（50池+320批次）**。320 批次导致过拟合/退化。**v6 用 32 批次是对的**。

## v7 — 混合头：理论推导否决，未开训

### 设计（2026-08-07 建立，`Gomoku-v0_pt_v7.py`）
- **结构**：v6 主干(8×ResBlock) + v6 极简 policy 头（conv(128→1,k3)→softmax 直出，无 fc 瓶颈）+ **v2 式双层 value 头**（value_conv + fc1(450→128) + fc2(128→1)→tanh）
- 脚本核实：`value_conv = Conv2d(conv_channels, value_channels, value_kernel)`（默认 k3 看棋形）、`value_fc1 = Linear(value_channels*225, value_hidden)`、`value_fc2 = Linear(value_hidden, 1)`
- **动机**：v6 极简头 value 稀疏盲区（黑活三黑视角 -0.91），v2 双层头 policy 梯度困 fc——**两个病在不同头上，混合 = 同时消灭**
- **理论依据**：v2 双层 value 在稀疏局面稳健（71-100% 无灾难性遗忘），128 维中间层 = 稀疏局面的"概念缓冲"
- 训练参数：未开训（若开训按 v6：800 sim / 温度调度 / α=0.03 / 5 代池 / 32×512 / lr 0.001）

### 拼权重快速侦察（5 分钟不训练）
- 方法：v6 it91 主干+policy + v2 it202 value 头塞进 v7 结构（value_kernel=1 与 v2 完全一致才能加载）
- 结果：黑活三黑视角 +0.678（vs v6 -0.91）——曾看似方向对，v7 思路一度被看好

### ❌ 败局库打脸（理论推导否决）
| 权重 | 败局库总正确率 | 黑 | 白 | MSE | 均值 |
|---|---|---|---|---|---|
| **v6 it91** | **51.7%** | 64.1% | 37.5% | 1.58 | -0.031 |
| v2 it202 | **37.8%**（低于随机）| 34.8% | 41.2% | 2.17 | +0.236（败局乐观）|
| v7拼(v6主+v2val) | 37.8% | 44.6% | 30.0% | 2.00 | +0.180 |

**结论**：
1. "v2 双层 value 好"是**手工局面碰对的假象**——真实败局库批量 v2 37.8% 低于随机、均值正（败局乐观）
2. **v6 it91 value 反而最好**（51.7%）：800 sim 数据质量 > v2 400 sim + policy 困 fc 拖累自对弈
3. **v7 拼 v2 value = 继承差 value**——v2 的 value 不值得继承
4. **v7 若做必须 value 头从 v6 value 头加宽双层 + 从头训练**（让 value 头适配 v6 主干），不能拼 v2——改动量大，且 v6 的稀疏盲区用数据增强就能修

**最终拍板：v7 不立项**。v6 value 底子其实好（51.7%），稀疏盲区用数据增强防遗忘就能修（改动小）；v7 换结构是更大改动，理论推导不通过（"v2 value 值得继承"前提被败局库证伪）。**验证脚本**：`scripts/v7_mix_verify.py`（拼法+手工局面）、`scripts/v7_badpositions_test.py`（败局库批量，可复用）。

## 关键规律总结

### 1. 架构决定学习机制
| 架构 | policy 学习 | value 威胁感知 | 后期风险 |
|---|---|---|---|
| 极简头（v1/v3/v6）| 无 fc 瓶颈，梯度直回传 | 天花板低（单层 fc）| 无深层退化 |
| 论文头（v2/v5）| **梯度困死 fc（92-97%）** | 强（双层 fc）| **深层 BN 塌缩** |

### 2. 模拟量决定数据质量 vs 数量
- **模拟量大** → 每样本质量高（policy 学得快）但慢迭代
- **模拟量小** → 迭代快样本多但 policy 目标近均匀（梯度≈0 → 饿死）
- v1 50 sim 期 policy 死；v6 800 sim 让 policy 活

### 3. 经验池深度有甜点位
- 5 代 = 最优（v2/v6）
- 50 代 + 320 批 = 灾难（v5，policy 拉平 + 有效秩腰斩）

### 4. 双头互相追赶是常态
- 一个头先起，另一个 15-30 代内追上 → **平衡期 = 棋力峰值窗口**
- v2：value 先起（it16）→ policy 追上（it32-60）→ 平衡（it45-150）
- v6：policy 先起（it16-18）→ value 追赶中（预计 it30-50）

### 5. 评测方法论铁律
- **loss 会骗人**：loss 降 ≠ 棋力升（v1 91/92、v5 反例）
- **模拟量必须匹配训练**：400 训练的权重用 800 评估 = 分布外（v2 it153 惨败）
- **贪心 vs 采样影响结论**：v6 it14 vs v2 it14 非贪心 14:6 → 贪心 11:9（采样红利放大差距）
- **PK 中途比分不可靠**：两次"领先 5 局被翻"实证，必须等完赛
- **单/少数手工局面会误导，必须败局库批量**：v7 差点因"黑活三 +0.678 看着对"立项，败局库批量 37.8% 直接否决——**判断 value 质量用 172 败局批量（正确率+MSE+均值），不用几个手工稀疏局面**

### 6. 颜色对称 ≠ 双视角健康（v8 新教训）
- v2/v6 单通道：方向对但**对称地盲**（200 随机镜像全 0.6-0.7，训 100 代治不好）
- v8 4ch：颜色对称**结构性满足**（代4 定向互补 0.0021 vs v6 it99 1.82）——但互补≠健康，随机 200 局面互补 0.51 仍近随机
- **结构性保证颜色对称只是第一步，双视角都要学到棋理才算真健康**——验收标准 = 堵活四

## 🔴 log概率bug 完整复盘（2026-08-10 发现）

### 一句话

**v2 把网络输出从 softmax 改成 log_softmax 时，只改了 learn 侧，忘了 search 侧要 exp——MCTS 先验从此反转，v2/v3/v6/v8 全部中招，v8 97 代训练白跑。**

### 版本溯源

| 版本 | forward 输出 | search 用法 | learn 用法 | 正确性 |
|------|-------------|------------|-----------|--------|
| **v1 原版（肖智清书）** | `F.softmax`（概率） | 直接用概率 | `torch.log(pred_p)` 算 CE | ✅ 正确基准 |
| **v2** | 改成 `F.log_softmax`（log） | **忘加 exp，log 当概率** | 直接用 log（简化 CE） | ❌ **引入 bug** |
| v3/v6/v8 | 继承 v2 | 继承 bug | 继承 | ❌ 继承 bug |

### bug 引入过程

```
v1:  forward = softmax(概率)
     search 直接用概率        ✓ 正确
     learn 里自己 torch.log    ✓ 正确
              ↓ v2 的"优化": log 提前到 forward, learn 简化
v2:  forward = log_softmax(log)
     learn 直接用 log         ✓ 这半是对的
     search 忘了 exp          ✗ 漏改! ← bug 源头
```

v2 的意图本身没错（learn 的 CE loss `-Σπ·log p` 直接用 log 概率），**但 search 的 UCB 先验必须是概率分布**（ub = q + c×prior，prior 要 ≥0 且量纲正确），v2 漏了在 search 里 `exp`。v3/v6/v8 复制 v2 的 search，一路继承。

### 后果（实测量化）

- **先验反转**：网络真实概率 11.55% 的必杀点（H6），log 归一化后先验只剩 **0.182%**（反转为"网络认为最差的点先验最高"）
- **UCB 选点反向**：修前 top = O2/J6/N1（网络最差），修后 top = H6/A15/H5（网络最好）
- **MCTS 乱选**：H6 必杀局面（白 H7-H10 四连），修前 50/100/400 sim 中 H6 访问 0 次或不在 top10，候选全错；**修后 50 sim 选 H6 93.9-98%**
- **之前所有 MCTS 相关结论需要复核**：活三探针（堵点不在 top10）、A15 飞点、MCTS 候选乱选、"policy 学不会开局"（实为网络已学会，是搜索层用反了）

### 为什么网络还是"学会"了

- **value 头**：训练目标 = 自对弈**终局真实胜负**（游戏规则判定），不经 MCTS 先验 → **不受影响**。只是搜索质量差 → 自对弈棋力弱 → 数据含金量低
- **policy 头**：训练目标 = MCTS 访问分布 = q引导(正常) + 反转先验(污染) + 噪声 + 终局强信号。**必胜点靠 q/终局信号（Q=+1）仍被大量访问** → 网络学得会"强信号点"；普通点排序被反转先验稀释 → policy 学得慢/不精准
- 所以 network_viz 直接测网络 policy 是对的（H6 11.55%），**但 MCTS 搜索层全程在错误先验下工作**

### 修复

### 观察报告 01：BN 参数对比（it114 同代，08-13 早间）

**双头 BN 是标量（1 通道归一化）**：policy_bn / value_bn 都是 σ=0 单值——policy 头 conv(1,128,3×3)→BN(1,)→log_softmax；value 头 conv(1,128,3×3)→BN(1,)→fc(1,225)。

**主干 BN（8块×2，128ch/层）全部 <1% 差异**：γ v9=0.592/v8=0.596，β 相同，rMean/rVar 相同——mom0.3 对主干 BN 参数形态无影响。

**深层 γ 收缩两线同形**：γ 从浅到深 0.68 → 0.61 → 0.54 → 0.45 → block7 仅 0.39-0.45——mom0.3 没有阻止深层 γ 收缩（这正是 mom03 想治的病，it114 看不出疗效）。

**唯一显著差异 = value_bn.running_mean**：v9=+0.275 vs v8=+1.034（4 倍差距）。
- PyTorch BN 公式：running = (1-m)·running + m·batch；mom=0.3 → 新 batch 占 30%（更新快），默认 0.1 → 只占 10%（更新慢）
- v9 rMean≈0 = BN 统计紧跟当前网络；v8 rMean=+1.03 = 统计滞后残留早期大均值（历史"BN 收缩/统计失配"问题根源形态）
- **mom0.3 的机制效果已在运行统计上显现**（value_bn 更快跟踪分布）

### 观察报告 02：双线趋势 it98-119（08-13 早间）
