## 一、段前背景：从 v36 王座到 v40 返璞归真

- **v36 是当时的最强网**：外部锚点 vs Rapfi depth5（恒执黑、修复后口径）`v36_it483` 约 **70.2%**（历史最高对外标尺，后续各版对标它）。v36 的破局点是「随机开局 3 手」，一举终结了 v18–v35 六代卡死的「白棋瓶颈」。出处：`blog_articles/CSDN_v36实战_番外二_白棋才是瓶颈.md`、`权重盘点_各版本最强.md`。
- **v37 → v38 → v39 走「教练法 / 轮次制」**（R1–R13）：每轮「冻结最新学成的那副网当教练 → 让上一轮的教练当学生继续学」，网络永不重置、黑白血统各自延续。机制与逐轮记录见 `教练赛谱系_轮次记录.md`、`轮次切换清单_v38_v39双槽.md`、`_pk_v8_pull/round_boundary_audit.md`。
- **但复杂教练法并未在绝对棋力上赢过朴素方法**（v36 朴素随机开局仍是标杆）。**用户拍板 v40 = 返璞归真**：回到最朴素的单网自对弈，剥掉教练法 / 多通道 / 随机开局等附加，用最干净的方式重验「颜色/开局」这两条老病根。

## 二、v40：单通道 canonical + 自由开局（2026-10-08 部署）

### 动机
返璞归真：以最简网络（单通道、无教练、开局全自由）重跑，看「朴素方法」能否同时把黑白都练好。

### 改动（vs v39）
| 项 | v39 | v40 | 备注 |
|---|---|---|---|
| 输入通道 | 4 通道 | **1 通道 canonical**（= `player*board`：当前玩家=1 / 对手=-1 / 空=0） | 还原 v1/v6 式单通道 |
| 随机开局 | `RANDOM_OPEN_MOVES=3` | **`RANDOM_OPEN_MOVES=0`**（开局完全自由，前 3 手全交模型） | v40 核心改动之二 |
| 教练法 | 有（v38/v39 教练 + 轮次制） | 无（纯单网自对弈） | |
| 其余 | sim=800 / lr=0.001 / 池 5 代 / 前 5 代 warmup | 同 | |

出处：`v40_训练配置清单.md`（单通道含义与逐行对齐验证见其第 1 节）。

### 结果：白崩；单通道也救不了白
逐代白胜率（数据源：`blog_articles/v40_丢长局假设验证_报告.md` 表一 + 本次对 `worker_data` 的 it38–47 复算）：

| 代段 | 白胜率 | 阶段判读 |
|---|---|---|
| it1–8 | 42%–54% | warmup + 健康期（白正常，黑白近均衡） |
| it9–13 | 40%–53% | **it10 网络能力跃迁**（健康探针「活四」0.016 → 0.97），池均手 58 → 26 |
| it14–16 | 17%–53% | **起崩点（约 it14）** |
| it17–24 | 8%–24% | 崩塌期（it21/22 = 8.9% / 7.8%） |
| **it38–47** | **均值 8.2%**（逐代 10.0 / 6.0 / 16.0 / 9.0 / 3.0 / 10.9 / 9.0 / 4.0 / 8.0 / 6.0） | 长期低谷，不动点成立 |

- **不动点成立 → 停**：白胜率长期锁死低位，训练不停但也无改善，遂停止 v40。

### 结论
1. **单通道 canonical 不救白**：v8 升 4 通道正是为修「重黑轻白」，v40 反向还原为单通道后白照样崩 → 证明病根不在通道数。
2. **「丢长局」假设被证伪**（重要）：把「主进程收满即 pkill 工兵、在途长局被丢」这条向下偏置**全部补回**，全体白胜率仅 **0.242 → 0.254（+1.2pp）**，远不足以解释 **0.45 → 0.10（−35pp）** 的崩塌。白崩的时间起点（it9→it10）与「网络能力跃迁」严格同步，而非与丢局机制同步。丢局是**真实但次要**的偏置，不是白崩的数据层根因。出处：`v40_丢长局假设验证_报告.md`。
3. **副产品（value 视角不对称）**：value 头「视角不对称度」末期暴涨（空盘 `|v_黑+v_白|` it20=0.070 → it23=0.786 → **it49=1.700**），但它**不领先于白崩**（白崩 it14，空盘不对称 it23 才爆）→ 更可能是**果 / 伴生现象，不是因**。出处：`v40_value视角不对称度_报告.md`。

## 三、v41：COLOR_SYM 视角对调增强（2026-10-09 部署）

### 做法
在 v40 单通道基础上打开 `GOMOKU_COLOR_SYM=2`（视角对调·模式 2）：对每个样本追加一份「对调视角」副本（**board 取负 + qa 取负 + policy 概率不变**），这份副本**只进 value 损失**，policy 只用原样本。目的：逼 value 头对「颜色镜像」保持一致，压制「黑方乐观」偏置。

### 结果：白从 8%–12% 抬到 24.8%（约 2.5 倍），但撞上 25% 天花板
| 指标 | v40（无 COLOR_SYM） | v41（COLOR_SYM=2） | 变化 |
|---|---|---|---|
| 白胜率（崩后） | 8%–12% | **24.8%** | 约 **2.5 倍** |
| 空盘 value 偏置 | 约 0.7–0.9 | 约 0.01–0.04 | **压制约 100 倍** |
| 均势局面不对称度 | 高 | 压低约 12 倍 | 明显改善 |
| 速杀（快攻）局占比 | — | 后期漂移到 43%–81% | **速杀漂移仍出现** |

- 空盘 value 的 v41 实值可由 `train_v41.log` 健康体检行佐证（长期 `空盘` = −0.04 ~ 0.04 区间震荡）；v40 空盘实值见 `v40_value视角不对称度_报告.md`（it23 起 0.4 → 0.85）。
- 出处：白胜率 / 倍数 / 天花板为项目 v41 实测记录与用户结论；**v41 的 `worker_data` 事后被清理，本次未二次复算白胜率**（诚实标注）。

### 根因洞察（重要）
- **COLOR_SYM 预设了「游戏颜色对称」，而五子棋颜色并不对称**（黑先手天然占优）。
- 于是「颜色对称约束」与「游戏真相」**冲突**：同一局面在黑白两种视角下本不应有相同价值，强制对称等于把网络往错误方向拉。
- 结果：网络被**拉在半路**（在「对称约束」与「黑优真相」之间动弹不得）→ **白胜率锁死约 25% 上不去**，这就是「25% 天花板」的机制解释。
- 结论：颜色对称是「加速器 / 缓解器」，**不是救命药**；对不对称游戏，颜色对称约束本身是**错约束**。出处：`v42_教练法自动换边_设计草案.md`（v41 结论引用），`版本演进史_v32_起.md` 中的 COLOR_SYM 段。

## 四、v42：教练法 + 自动换边（当前，2026-10-10 13:33 起训）

### 基础
- **底座 = v39 教练法**（学生 vs 冻结教练）+ **从 v41 移植梯度检查点 `GRAD_CKPT`**：压 `learn` 阶段激活显存峰值约 **56%**，已验证与不开数学等价（Δ=0）。
- **v42 = 4 通道**（继承 v39 血统，零移植）。注意：v42 不是单通道，它**自带颜色通道**（ch0 当前玩家 / ch1 对手 / ch2 恒 1 / ch3 上一步），所以 PK / 评测时可**指定执色**。
- 从零训练（无种子权重）。

### 机制：学生 vs 冻结教练 + 自动换边
- **学生 = `weights.pt`**（在学）；**教练 = `weights_coach.pt`**（冻结，本地推理，不走共享服务）。
- **触发**：本代学生胜率 **不低于 55% 且连续 2 代** → 自动换边。
- **防抖**：两次换边最短间隔 **5 代**，换边后 streak 清零（防「刚换又换」导致工兵反复重建、吞吐崩）。
- **换边动作（原子对调）**：① `weights_coach.pt ← 学生`（学生冻结为新教练）；② `weights.pt ← 原教练`（原教练转正为新学生）；③ **教练色取反**。净效果 = **两网互换【角色】，各自【执色不变】**（设计草案 二.4 原文：「新学生走它原本执的色，新教练走它原本执的色」）。
- **真相源 = `swap_state.json`**（env 改不到已在跑的工兵，必须落文件；否则换边瞬间工兵用旧教练色 + learn 用新剔行色 → 样本静默混色污染）；另记 `round_ledger.jsonl`。
- **首个教练 = 初始权重快照**（`weights_coach.pt ← weights.pt`，完全自举：学生与教练同权重起步，一黑一白对打，初期约 50% 后逐步拉开）。

### 配置
`COLOR_SYM=0`（关闭）/ 从零（无种子）/ 换边不清池 / **20 工兵 x 6 局 = 120 局/代**（收满 100 即训）/ 池 5 代 / sim=800 / `RANDOM_OPEN_MOVES=0`（开局完全自由）/ `LATE_MERGE=1`（长局不再丢）/ `GRAD_CKPT=1`。出处：`start_v42.sh`、`gomoku_checkpoints_v42/metadata.json`。

**「黑棋权重 / 白棋权重」的准确表述**：
- 【错】 **不能说**「`weights_it6_v42.pt` 是（固定的）白棋权重」就完事 —— 它是「**第 2 轮（学生执白）的学生快照**」；脱离轮次与角色，颜色无意义。
- 【错】 **也不能说**「某个文件在所有轮次执同一色」——因为**学生这一角色的色逐轮翻转**；同一个可变文件 `weights.pt` 在第 1 轮执黑、第 2 轮执白、第 3 轮又执黑（内容每次被换边改写）。
- 【对】 **准确说法一（角色视角）**：「第 X 轮时，学生执 Y 色、教练执 Z 色；`weights_itN` 是第 X 轮的学生快照」。这是本表采用的表述。
- 【对】 **准确说法二（网络身份视角，机制真相）**：换边是「两网互换**角色**、**各自执色不变**」。实测佐证：第 2 轮的**黑教练 it5** 在第 1 轮就是**黑学生**（两轮皆黑）；第 3 轮的**白教练 it14** 在第 2 轮就是**白学生**（两轮皆白）。权重距离也印证：`it15` 与 `it5` 的距离（0.0141）明显小于与 `it14` 的距离（0.0178），即第 3 轮黑学生是从 **it5（黑网）** 续训，而非从 it14。
- **「同一份权重执不同色」的真正出处 = 自举起点**：初始权重 **it0 被同时克隆成两份** —— 一份当第 1 轮**黑学生**（`weights.pt`），一份当第 1 轮**白教练**（`weights_coach.pt`）。**同一份张量，一黑一白**；该副本随后又在第 2 轮当**白学生**的起点。所以「同一权重可执不同色」成立于**起点克隆**这一环，而非任意文件。
- **PK / 评测口径**：v42 是 **4 通道**网络，自带颜色通道，PK 时**指定谁执黑谁执白**即可；「黑棋权重 / 白棋权重」在评测语境里应表述为「**用哪一轮、哪个角色的快照（如 it14 第2轮白学生 / it5 第2轮黑教练），让它在 PK 里执哪一色**」。

### 关键观察
- **「黑吃瘪」现象**：第 3 轮黑学生从 **it5**（只训过 4 代）恢复，对上强教练 **it14**（白网，训过 9 代），胜率一度掉到 **22%**，再震荡回升（22 → 30 → 33 → 42 → 24.8 → 22 → 36）。这正是**「教练阶梯上升」的体现**：每换边一次，冻结的教练就是上一轮刚达标的**更强**网络，新学生得从头追赶教练 —— 于是表现上出现「新学生先被教练压着打（吃瘪）、再逐步追平反超」的锯齿。policy_loss 同步从 5.42 降到 5.3256 也在追这一台阶。
- **待验（未证）**：换边十几轮之后，把当时的黑白网分别上 **Rapfi 外部评测**，看**绝对棋力**（对标 `v36_it483` 的 70.2%）。在此之前，「学生胜率不低于 55%」只是**内部相对口径**，**不等于**绝对变强 —— 必须用 Rapfi 这把外尺才能判定 v42 是否真的比 v36 更强。
