## v24b：黑方空盘首手走「value 最均衡」的一手

**动机**：验证「平衡开局能否抬高白方胜率」。原版白方在随机网阶段首手近似随机落子，
黑方由搜索决定，两侧开局质量不对称。

**改动（唯一行为改动）**：`move_no == 0` 时，在中心 5×5 内每个空点试落本方子，
取 `|value|` 最小的前 K 手随机挑一个。

| 开关 | 默认 | 说明 |
|---|---|---|
| `GOMOKU_BALANCED_FIRST` | 0 | 1=启用 |
| `GOMOKU_BALANCED_REGION` | 5 | 候选区域边长（中心 5×5） |
| `GOMOKU_BALANCED_TOPK` | 10 | |V| 最小的前 K 手里随机（3→10 是为了开局多样性） |

**过程中修掉的两个坑**（都是实测发现的）：

1. `move_no == 0` → `move_no <= 1`：**只限黑方会让黑方白得一个中心子**，对照组被污染。
   改为白方首手也走均衡手（对称化），实测 93 局黑白首手 100% 落在中心 5×5。
2. `torch.compile` 默认开启（`mode='reduce-overhead'` = CUDA Graph）时，**每步前向的 batch
   大小都不同 ⇒ 每个形状都要重新 capture ⇒ 单次前向 919ms**（正常 2.3ms）。
   主进程因此 493~939 秒/局。改为默认 `disable_compile=True` 后 73.5 sims/s。

**实测结果（代1/代2）**：

```
代1：均手 51.5 ｜ 白胜 45% ｜ 速杀 0%
代2：均手 57.6（中位 58，最长 99）｜ 白胜 48% ｜ 速杀 0%
体检：代1 冲四 ✅ → 代2 活四 ✅（先学会"看威胁"，不是"造威胁"）
```

**结论：均手没有下降，反而 51.5 → 57.6（v24 原版代2 是 38.9）。判为路线偏离。**

**根因（探针实测，见下节）**：`min|V|` 这条规则选的是「网络最没意见的一手」，
而**贴身这一手的 |V| 恰好最大 ⇒ 被系统性排除**。

## v24c：改成 AlphaGomoku 式「开局过滤」（当前版本）

### 决策依据：为什么 v24b 的清单手规则是错的

探针（weights_it2，黑子固定 H8，白方视角 value，正=白好）：

| 离黑子距离 | 平均 V | **平均 \|V\|** | 最正 V |
|---|---|---|---|
| 1 格（贴身） | +0.0364 | **0.1782 ← 最大** | **+0.2510（H7）** |
| 2 格 | **+0.0578** | 0.0750 | +0.1755 |
| 3 格 | +0.0089 | 0.0315 | +0.0600 |
| ≥5 格 | +0.003~0.005 | 0.024~0.028 | — |

- 中心 5×5 内 `|V|` 最小的 10 个点 **全部是 2 格**，一个贴身都没有
- `|V|` 最大的 5 个点里有 4 个是 1 格（含 V=+0.2510 的白方最优手 H7）

⇒ **规则把"白方价值最高的贴身手"整类排除了**，白方永远被推到"中性 2 格"。

次手到首手距离（切比雪夫）：

| | 距离 | 贴身≤1 | ≥3格 |
|---|---|---|---|
| v24 原版 代1 | 6.10 | 7% | 92% |
| v24 原版 代2 | 3.48 | 50% | 42% |
| v24 原版 代3 | 3.47 | 21% | 64% |
| v24 原版 代20 | 3.04 | 39% | 40% |
| **v24b 代3（均衡首手）** | **2.51** | 23% | 49% |

⇒ 我们不但没让白方跑远，反而更贴；问题是**"贴哪一格"被规则锁死在 2 格**。

### 采纳的外部方案（出处登记）

- **仓库**：`github.com/MaciejKozarzewski/AlphaGomoku`（Gomocup 2026 Freestyle 15×15 第三名）
  分支 `master`，HEAD `1f81840`
- **文件**：`src/selfplay/OpeningGenerator.cpp`（`generate`，约 44–56 行）、
  `src/utils/misc.cpp::prepareOpening`（142–168 行）、`src/selfplay/GameGenerator.cpp:25,73`
- **原始逻辑**：

```cpp
// OpeningGenerator.cpp：只收 |V-0.5| < 0.1 的开局，超了丢弃重抽；阈值随 trials 放宽
const float balance = std::fabs(iter->task.getValue().getExpectation() - 0.5f);
if (balance < (0.1f + 0.01f * trials)) { completed_openings.push_back(iter->moves); trials = 0; }
else trials++;

// misc.cpp::prepareOpening：开局本体 = 随机 0~15 手，中心加权；1‰ 概率 0 手开局
int opening_moves = std::max(minNumberOfMoves, randInt(6) + randInt(6) + randInt(6));
if (randInt(1000) == 0) opening_moves = 0;
```

- **妙在哪**：筛选器用的是**当前网络自己的 value** ⇒ 网络弱时自动丢掉"一边倒"的开局，
  网络变强后接受集合自动迁移，不需要人工维护开局表；训练分布里不会出现一边倒开局。

### 我们的实现（`Gomoku-v0_pt_v24b.py`，env 开关，默认关）

| 开关 | 取值 | 说明 |
|---|---|---|
| `GOMOKU_BALANCED_FIRST` | **0** | 清单手规则关闭 |
| `GOMOKU_OPEN_FILTER` | **1** | 开局过滤开启 |
| `GOMOKU_OPEN_VTH` | **0.25** | 阈值（我们 value 标度 [−1,1]，0=均势） |
| `GOMOKU_OPEN_VTH_STEP` | 0.02 | 每次重抽放宽（AG 是 +0.01，标度换算 = 0.02） |
| `GOMOKU_OPEN_TRIALS` | 12 | 最多重抽次数，全不过则退回 0 手开局 |
| `GOMOKU_OPEN_MAX` | 15 | 开局手数上限（0~15，中心加权） |

**流程**：双方在中心加权下随机下 0~15 手（不做搜索，只 1 次前向/手）→ 评估 `|V|` →
`|V| < 阈值` 采用，否则整局丢弃重抽（阈值 +0.02）→ 从该局面继续正常 MCTS 自对弈，
温度调度从开局手数接着走。开局那几手的 policy 目标 = 网络自己的原始策略。

### 阈值怎么定的（实测，不猜）

60 局随机开局（均值 7.8 手）结束时的 `|V|` 分布：

```
P10 0.018 ｜ P25 0.046 ｜ P50 0.128 ｜ P75 0.214 ｜ P90 0.316 ｜ max 0.484
```

| 阈值 | 接受率 |
|---|---|
| 0.10（= AG 的 0.1 换算值，但我们的网更弱） | 38%（太严） |
| **0.25（选定）** | **≈80%** |
| 0.50 / 0.60 | **100%（= 不过滤，因为 |V| 从来不到 0.484 以上）** |

重抽成本几乎为零（开局不做 MCTS，被拒一局只浪费 ~8 次前向 ≈ 0.02 秒），
所以阈值只看"想要多宽的训练分布"，不看成本。

### 已知风险

1. 开局段是随机手，policy 目标弱信号（网络原始策略近均匀）⇒ 开局几手学得慢
2. 若 12 次重抽全不过（阈值升到 0.49），退回 0 手开局 —— 极端情况会有一局"无开局"
3. 开局分布变宽后，早期对局可能更乱（双方都可能飞到边角）⇒ 速杀率可能先上升

### ★ 机制结论：过滤器会偏向"网络没意见"的开局

```
过滤器判据 = |V| < 阈值 ⇒ 它筛的不是"客观均衡"，而是"网络看不出好坏"
而网络的意见恰恰来自贴身/接触局面（探针实测：离黑子 1 格的 |V|=0.178，≥5 格只有 0.024）
⇒ 越散的开局 |V| 越小 ⇒ 越容易被放行
⇒ 于是"重抽率越高 → 留下的越是安静/分散的开局" → 布局偏散（最近邻距 2.0~2.4）自洽闭环
```

这不是 bug，是"用当前棋力判均衡"的必然结果（网络变强后这些开局也会被它自己判掉）。
代价：网络越强，越偏爱"它看不懂"的开局；好处：训练分布里不会出现它一眼看穿的屠杀局。

## ★★★ 方法论：换数据 > 骗网络（开局过滤 vs 分类采样补偿）

### 两种方案的本质区别

| | **v4 分类采样补偿**（分层 35-10-22-33） | **v24c 开局过滤**（\|V\|<0.25） |
|---|---|---|

| 训练数据 | 被改写：白方走时"白赢"占 **40%**（真实 12%） | 全是真实对局，无加权 |
| 治的是什么 | 标签分布（症状） | 开局结构（病因） |
| 额外负担 | 维护"白赢储库"（19200 条 / 36MB / 每40局落盘 / 重启载入） | 无（重抽 0.05 秒/局） |

### 指标上的铁证

| | v4（分类采样补偿） | **v24c（开局过滤）** |
|---|---|---|

| 均手 | 19.1 | 15.9 |

**空盘 value +0.964 = "网络坚信黑方必胜"的幻觉**，而这幻觉正是分层采样喂出来的：
batch 里"白方走时白赢 40%"，真实只有 12% ⇒ value 头学会"白方处境很好"的假象
⇒ **认知（0.96）与行为（白胜 6.7%）严重背离**。

我们的 0.087 对应白胜 46%（回归公式预测 40.6%）⇒ **认知与行为一致**。

### 为什么"换数据"比"骗网络"强

```
① 骗网络 = 给网络看一个不存在的世界
   ⇒ value 学到"统计学幻觉"，遇到真实局面就错
   ⇒ v4 的 0.964 / 6.7% 就是幻觉的代价

② 换数据 = 只让网络看见真实但更均衡的世界
   ⇒ 标签天然均衡，不需要加权
   ⇒ 顺带治了"局本身一边倒"的问题（从源头）

③ 成本更低：过滤 0.05 秒/局 vs 储库 36MB + 落盘 + 重启载入
```

## ★★★ 退化回路的根因：高温采样污染训练数据（2026-11-18 夜，实测）

### 实测方法

M4 本地跑 20 局真实自对弈（it87 权重，口径与训练完全一致：OPEN_FILTER=1 / VTH=0.25 /
OPEN_MAX=15 / sims=800），拦截 `decide()` 记录每手的 `move_no` 与 `temperature`。

```
步长：均 20.5 ｜ 中位 15 ｜ 最短 9 ｜ 最长 40
开局手数：均 5.5 ｜ 中位 7 ｜ 范围 0~12（20 局中有 5 局开局=0 手）
网络段首手温度均值 0.74 ｜ 末手温度均值 0.27 ｜ 网络段均温 0.48
```

| 步长区间 | 局数 | 网络段均温 | 末手温度 |
|---|---|---|---|
| **0~13 手（短局）** | 7 | **0.79** | **0.48** |
| 14~20 手 | 5 | 0.49 | 0.30 |
| **21~40 手（长局）** | 8 | **0.20** | **0.06** |

**短局 = 高温区（0.79），长局 = 接近贪心（0.20）。**

### 大样本交叉验证：短局几乎全是黑胜

| 代 | 短局(≤13手) | 短局黑胜率 | 长局黑胜率 |
|---|---|---|---|
| 43 | 28 局 | 75% | 60% |
| 60 | 25 局 | **96%** | 51% |
| 75 | 31 局 | 84% | 58% |
| **88** | **40 局（占 42%）** | **92%** | 47% |

### ★ 完整退化回路

```
① 温度调度按「绝对手数」衰减：第1手 1.00 → 第13手 0.31 → 第20手 0.14
   ⇒ 对局若在 13 手内结束，全程处于 0.4~1.0 高温区

② 高温 = 按 MCTS 访问分布采样 ⇒ 近似随机走子
   ⇒ 随机对下时先手（黑）几乎必胜（92%）

③ 这些「高温随机黑胜局」占全部对局 30~42%
   ⇒ 喂给 value 头 ⇒ value 学到「黑从开局就赢」
   ⇒ 空盘 V 实测漂移：0.230(it63) → 0.348(it58) → 0.370(it71) → 0.381(it78)

④ 空盘 V 上升 ⇒ 开局过滤器在【空盘】就通过
   阈值 = 0.25 + 0.02 × 重抽次数（12 次上限 ⇒ 0.49）
   空盘 V=0.381 时，第 7 次尝试（阈值 0.39）即通过，手数=0
   ⇒ 实测 20 局中 5 局（25%）开局手数为 0，完全没做开局随机化

⑤ 无随机开局 + 温度从第 1 手就是 1.00 ⇒ 又是高温随机局 ⇒ 回到 ①
```

**闭环：温度高 → 黑速胜 → V 升高 → 开局过滤失效 → 温度影响更大。**

### 这解释了过去所有「看不懂」的现象

```
· 空盘 V 单调上涨：是高温随机黑胜局喂出来的，不是棋力变化
· 均手低、短局多（42%）：短局是高温产物，不是防守变差

· 「活三不堵」：短局里是随机走子；中盘 17~25 手贪心测也只有 22%（另一层问题）
```

### 结论

```
不是网络在退化，是【训练数据被自己的高温采样污染了】。
短局不是棋力下降的表现，是「随机对下」的表现，而我们把它们当成了教学样本。
```

## ★★★ 反转机制定案：温度锁 + 短局占比（2026-11-19，用户假设 → 实测验证）

### 用户假设

> 「昨天活三不堵，是因为遇到了温度锁 —— 堵点概率不够高，被高温采样锁住了。
> MCTS 搜得出堵点，但温度把它稀释掉。现在堵点概率应该提高了很多。」

### 实测方法

固定 **263 个活三局面**（全部取自代105，手数 ≥13），用三个不同网络分别判 policy，
统计：p(堵端) 总概率 / argmax 是否落在堵端 / 在不同温度下的实际落地率
（落地率 = softmax(log p / T) 在两个端点上的概率和）

### 结果

| 网络 | p(堵端)均值 | **argmax 堵端%** | T=1.0 落地 | T=0.5 落地 | T=0.3 落地 |
|---|---|---|---|---|---|
| it43 | 21.4% | **44.9%** | 21.4% | 39.0% | 43.3% |
| it88（前一天） | 26.1% | **36.5%** | 26.1% | 35.3% | 37.2% |
| **it105（今天）** | 23.7% | **49.4%** | 23.7% | 40.2% | **45.1%** |

**假设成立**：argmax 堵端从 36.5% 恢复到 49.4%（+12.9pp），甚至超过代43（44.9%）。

### 但有个精确的细节：涨的是「判断」，不是「总概率质量」

```
p(堵端) 总概率：26.1% → 23.7%（略降）
argmax 堵端    ：36.5% → 49.4%（大涨）

⇒ 现在更常把堵端排第一，且排第一时更果断
  （以前两端各分 ~13%，现在一端 ~20%、另一端 ~4%）
⇒ 所以「总质量」没涨，但「决定性」大涨
```

### 完整体温账（这正是温度锁机制）

```
中盘 17~25 手实际温度 0.14~0.07 ⇒ 落地率 ≈ argmax ≈ 49%
前一天（it88）同一批局面只有 36.5%
前 6 手温度 1.0 ⇒ 落地率只有 23.7%（高温段依旧锁死）

⇒ 高温段没被修好，只是【高温段的局面变少了】：
  短局(≤13手) 占比 54% → 24%
```

### 反转的真实机制 = 两条叠加

```
① 判断本身恢复：argmax 堵端 36.5% → 49.4%（回到/超过代43）
```

### 四、判据表（看门狗自动给答案）

### 五、结论

