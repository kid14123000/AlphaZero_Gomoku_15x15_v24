#### 完整解读（08-14）

**① BN γ 解读**：v10 γμ 单调微升（1.012→1.042，+4%）= 梯度自由演化的自然动态，**健康态**（γ 健康工作区 0.1-10，跌向 0 才是死亡——v8 γmin 0.577 逼近 0.08 危险线）；**关键佐证 = rVar 稳定 0.31-0.39**（归一化统计没乱，γ 涨是信号放大非失效）；监控线 = γμ>2-3 / rVar 塌缩<0.05 或膨胀>5 / γ 指数加速拐头。v8 跌是 wd 机械压制，v10 涨是梯度自由——**涨是活，跌是死**。it50 预期 γμ ~1.05-1.08。

**② 体检解读**：value 13 代全绿 = v10 value 头健康度碾压 v8（8 次波动）；policy 黑威胁组 v10 提前 6+ 代达标；**白威胁组 v10 的盲更顽固**（v8 白守 it17 过，v10 白攻/黑守 13 代没动）——与 A15 一致。

**③ 败局库解读**：v10 均值 42% vs 39.5%（+2.5pp）；波动形态差异大——v10 无深谷（32.6-48.3），**v8 it15 崩 20.3%**（健康窗口随机对齐）；乐观偏置 v10 更小（it19-20 接近 0）；⚠️ it21-22 v10 回落 v8 追平（单代波动 vs 趋势，it30 确认）。

**④ 分层解读**：v10 value_fc L2 小 20% = 更小幅度更好棋力（体检/败局库排除欠拟合）；r7 conv2 v10 稳定 vs v8 增长 = v8 深层"费劲补偿"（BN 死后挣扎），v10 无此压力。

**⑤ 布局解读（最需警惕）**：it12 曾有稳定中心定式 (5,5)×21（v8 同期没有）；**it16 起边角化抬头**（(4,0)×12 → (3,0)×7，首手边角 52%/49%，中心 16-20%）——v8 是 it45+ 才稳定恶化，**v10 22 代就有苗头，比 v8 早**；全对局边角 33-37%（基线 27%）未失控。it30 必复查（>45% = 真实趋势，回落 = 波动）。

**⑥ 空盘先验解读**：v10 it10-14 天元 (7,7) 2.3-2.8%（**学过中心**），v8 无强中心期（it14 top10 甚至四角）；后期都摊平（空盘近均匀是 v1-v8 常态，不可判病）。**v10 中心意识曾存在但被摊平覆盖**——与⑤形成张力。

**⑦ 空盘 value 解读**：v10 稳定 +0.03~0.05（11/13 代正，it16 单代波动）="先手略优"正确认知；v8 10/13 代负（反常识）。**policy 中心起手 + value 先手略优的组合 v8 全程没有**。

**⑧ 深度解读**：v10"黑眼睛"（黑威胁识别）全面好、"白眼睛"（白威胁）13 代没长——**PK 白窗口 2:3 的机制层解释**。

**综合预测（供 it30 验证）**：边角化若是真实趋势 → it30 首手边角 >45%；若是波动 → 回落 35-40%。白视角短板 it50 前改善概率低（13 代没动静），it50 PK 白窗口大概率仍失分——但黑窗口保持 4:1+ 压制则总分仍可赢。

## v11 — BN→GN 备用方案（08-14 登记，计划中未部署）

### 定位

**备用方案**（用户 08-14 拍板）：v10 基础上唯一变量 = 全部 `BatchNorm2d` → `GroupNorm`，其余与 v10 完全一致（含 optimizer BN 参数 wd=0 分组逻辑）。代码本地备好，不部署、不影响 v10 训练。

### 为什么考虑 GN（08-14 分析）

BN 在本项目已确诊的故障模式，GN 全部结构性免疫：

| BN 故障模式（v8 实锤） | GN 的行为 |
|---|---|
| running stats 滞后于权重演化（rVar 缩水 6 倍 = 归一化失效） | **无 running stats**，逐样本统计，永不滞后 |
| batch 统计依赖（batch=512 波动） | **逐样本归一化**，与 batch 无关 |
| 单样本前向（PK/探针/MCTS 节点）用 running stats，与训练有 gap | 训练/推理**行为完全一致** |
| γ 被 wd 压 → 死亡螺旋（需 wd=0 治疗） | 无 batch 统计放大效应，γ 收缩风险天然更低（仍有 γ/β 需 wd=0 保护） |

**对 MCTS 800sim 单样本逐节点前向特别友好**：BN 的 running stats 永远在追赶权重，GN 从机制上消灭这个"追赶"问题。

### 风险点（提醒以后的我们）

1. **偏离主流**：AlphaZero 原版及主流复现（Leela 系）都用 BN，GN 在棋类 RL 验证少——这是**冒险**不是常规操作
2. **大 batch 下 BN 通常略优**：GN 丢掉 batch 统计的跨样本正则效应（本项目 batch=512 中等，影响有限但存在）
3. **GN 组数是新超参**：128 通道 G=32（默认）需固定，避免"唯一变量"掺入第二个变量
4. **checkpoint 不兼容**：GN 无 running stats，v10 权重无法加载，**必须空池重训（~4-5 天）**
5. **🚨 optimizer 分组检测必须同步改**：`'bn' in name` → `'gn' in name`，漏改 = GN γ/β 被 wd=1e-4 压 = v8 死亡螺旋原样复发（"只改一点"经典坑）
6. **诊断工具链全要适配**：bn_trend/bn_cmp/health 的 running_var/bn_dead 检测 → GN 无 rVar，γ 检测改 'gn' weight
7. **机器资源**：只有老机一台在跑 v10，v11 启动 = 停 v10 重来（无法并行 A/B，只能顺序）

### ⚠️ 前提提醒（用户 08-14 强调）

**如果 v10 关 wd（BN 参数 wd=0）效果好，就不需要 v11 这个冒险方案**——v10 是已验证方向的渐进修法（改动最小、继承 BN 主流、成本 0 额外），v11 是结构性替代（收益更大但偏离主流、要空池重训）。**v11 只在 v10 明显失败时才考虑启用**，不要因为"GN 听起来更彻底"就主动换——求稳优先。

### 关键陷阱

- **optimizer 分组检测 `'bn' in name` 必须同步改 `'gn' in name`**——漏改 = GN γ/β 被 wd=1e-4 压 = v8 死亡螺旋原样复发（"只改一点"经典坑）
- checkpoint 不兼容（GN 无 running stats）→ v11 必须空池重训
- GN 组数超参：128 通道选 G=32（默认）需固定，保持"唯一变量"干净
- 诊断工具链适配：bn_trend/bn_cmp/health 的 running_var/bn_dead 检测 → GN 无 rVar，γ 检测改 'gn' weight

### 决策链（用户 08-14 拍板）

## v12 — 每局 reset MCTS（根治"一代一树"bug，2026-08-15 启动，当前主线）

### 定位

v10 判废后的重练主线。**唯一改动 = self_play 每局开头 `agent.reset_mcts()`（回到标准 AlphaZero 的"每局独立搜索树"），其余与 v10 完全一致（含 BN 分组 wd=0）**。起因 = 发现书版继承的"一代一树"实现缺陷（v1→v10 全部版本中招）。

### 为什么（"一代一树" bug 完整机制，2026-08-15 发现）

**一句话**：self_play 每局之间不清理 MCTS 状态（count/q/policy 字典）→ 空盘局面 key 跨局串扰 → 局 2-10 复用局 1 的搜索分布 → 首手定式 + 探索独立性被破坏 + 偶然错误放大。

**源码事实**（v1 original / v8 / v10 逐版核实）：

```python
def self_play(env, agent, ...):
    observation, _ = env.reset()
    for step in itertools.count():
        action, prob = agent.decide(...)   # decide 内部不 reset
        ...
    # ← 每局结束: 没有 agent.reset_mcts()!

def decide(self, observation, ...):
    while self.count[s].sum() < self.sim_count:
        self.search(...)                    # 不清 MCTS 状态

# reset_mcts 只在三处:
#   __init__ / learn() (每代训练完) / load_checkpoint()
```

**跨局串扰机制**（实测验证）：

```
局1: 空盘 decide → 搜索 800 次 → count[空盘].sum() = 800
局2: 空盘 decide → while 800 < 800 = False → 一次都不搜索!
     → 直接用局1空盘的 count 分布决策首手 (temperature 采样)
局3-100: 同上 (一代内全部复用局1分布)
```

**书原版对照（rl-book 原始代码确认）**：用户下载的 `rl-book-master/zh2019/code/chapter11_alphazero/TicTacToe-v0_tf.ipynb`（书第 11 章原版）**同样每局不清理**（self_play 复用 agent、decide 不 reset、learn 才 reset）——**"一代一树"是书代码的写法，我们 v1→v10 忠实继承，不是中途改坏**。但书原版 TicTacToe（3×3 小棋盘 + 每代局数少 + sim 少）影响极小；我们放大成五子棋（15×15 + 100 局/代 + 800 sim）后爆发。

**✅ 作者官方确认（2026-08-16 用户直接询问肖智清博士，勘误成立）**：肖博士回复——"谢谢您的反馈。经核实，我给出的代码确实没有在每局开始时重置搜索树，实现不当。谢谢您的勘误。"——**"一代一树"确认是书代码的遗漏（非设计选择），我们的诊断与修复方向（每局 reset 回到标准 AlphaZero 设计）得到原书作者背书**。涉及文件：GitHub `ZhiqingXiao/rl-book` zh2019 第11章 `TicTacToe-v0_tf.ipynb` + 官网 en2024 代码页（torch/tf 两版）。

**标准 AlphaZero 设计**（DeepMind 论文 + alpha-zero-general/Leela Zero/KataGo 一致）：**每局 self-play 开始构建全新 MCTS 树（空盘根）**，局间树/统计绝对隔离——不同局的搜索没有共享意义，且空盘根跨局串扰会固化开局。

### 后果（实测量化，⚠️ 2026-08-15 回放池全程实证修正）

| 现象 | 数据 |
|------|------|
| 首手多样性（v8 it0-215 / v10 it0-77 回放池全程）| **组内（每工兵10局）去重 7.5-10.0、组内定式率 0%**——温度采样（T=1）保护了多样性；全代去重 57-84 种 |
| ~~首手定式（v8 it99+ 90% 同首手）~~ | ❌ **回放池复现不了**（原说法是 v8 后期极聚焦特例/口径差异）——真影响见下行 |
| **🚨 边角爬（真正的数据污染）** | **v8/v10 全程边角占比 28-62%**（v8 it0 就 60%、v10 it0 就 50%、v10 it64 62% 峰）——局1 空盘搜索分布（value 边角乐观 → Q 推偏）被 10 局复用固化 → 整代边角首手 → 数据堆积 → policy 学歪（v10 it50 锁四角、实战首手恒 (3,0)） |

**关键认知修正（用户 08-15 纠正 + 回放池实证）**：不是"一代 1 颗树共享 100 局"——是 **1 主进程 + 9 工兵 = 每代 10 颗独立 MCTS**（进程隔离），每颗服务 10 局。**"组内定式/90% 同首手"是早期误判**（回放池全程组内定式率 0%，温度采样保护）；bug 的真实影响 = **① 空盘首手分布被局1 搜索固化（无噪声修正）② 边角爬数据堆积（28-62%）③ 探索噪声失效**。这也解开了"policy 空盘中心强（22%）vs 回放池首手边角多（51%）"之谜——policy 先验正确（中心），搜索（局1）把分布推偏边角，固化+堆积后学歪。

### 为什么这个 bug 潜伏这么久

- **书版就有**（TicTacToe 小棋盘影响极小）

- v8/v10：搜索修复（exp bug）后 policy 聚焦 → 首手确定 → 撞树率飙升 → 定式暴露（it99+）
- **早期实测首手多样（60-74 种）曾误导"没问题"**——但组内（每工兵 10 局）定式 + 后期聚焦爆发才是真相
